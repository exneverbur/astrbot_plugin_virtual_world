# 提示词与上下文

[文档目录](README.md) · [按主题拆开的详细说明](GUIDE.md) · [返回 README](../README.md)

每一轮她看得到什么、群聊上下文怎么带、token 预算怎么算。

## 她看得到什么

每次组提示词时都会带上这些，越靠前越重要：

| 内容 | 说明 |
| --- | --- |
| **现在的日期时间** | 运行时状态的第一行：`现在是：2026-09-12（周六）23:40 —— 深夜`。没有它，模型分不清"深夜该去睡"和"白天犯困才小睡" |
| 当前场景 | 在哪、氛围、这里能做什么、**从这里出发去每个地方要几 tick**（含 id，按距离排序，走不过去的会标出来） |
| 状态数值 | 每个值都带 0~1 的范围和高低两端的含义，心潮还会给一句程度描述 |
| 今天的基调 | 每天掷一次的那一种（懒散 / 活跃 / 黏人 / 想独处 / 说不上来），写成一句"今天这一整天的底子"，并说明不用刻意说破、让它渗进反应里就好。掷到"平静"（多数日子）时这一行不出现 |
| 想找的人 | 控制台页那一行：正在惦记谁（想念值 / 阈值）、**刚聊过还在冷却里的人**（还要多久才会开始想）、今天还剩几次主动找人额度。想念值只跟"他多久没找过她"和孤独感有关，跟她自己的忙碌无关——群里别人刷屏不算陪过她 |
| 手头的事 | 正在做什么（还剩几 tick）、计划里还没做的（带这份计划的原因）；手头空着时补一句「你上一次安排好的是：…」，免得每轮从零重想 |
| 最近发生的事 | 她**真的做了什么**：走动、做饭、伸懒腰、被人打断…（最近 5 件，更早的去日志看）。光开口说话 / 心里想一下**不列在这**——那些在聊天记录和「你最近说过的话」里已经有了；渲染不成人话的碎片记录（"发言等待回应"之类）也不列，省得糊一行原始数据给她 |
| 内心活动 | 最近一次推理草稿（在哪 / 状态 / 心情 / 在和谁说话 / 打算怎么办） |
| 记忆 | 这个地点、这个人相关的场景记忆，**每条带日期和时段**（`[09-11 晚上] 她说想换工作`），并且按时间从早到晚排——越靠下越新 |
| 群聊上下文 | 一条按时间排的对话流：别人的话带昵称和 id，她自己的话标成「你:」；合并转发会注明。她说出去的话都算——被 @ 的接管回复和主动发言都会记下来，下一轮不会被要求重复同一个句式 |
| 是不是在对她说 | 被 @、私聊、叫了她的名字、或者紧接着她那句话往下说 → 按「对你说」处理；其余一律按「群里在聊，她去插一句」处理，提示词会写明「没有人点名找你」，免得她把别人的闲聊当成对自己的请求 |
| 上次跟他说话是多久前 | 在「你在跟谁说话」里：`他上次跟你说话是 2 小时前；他 3 分钟前在群里露过面`。两个时间分开说——他在群里刷屏但没找过她，一眼看得出来。没有这一行，"你昨天说的那个"就落不了地 |
| 她平时怎么说话 | 从「声音样例」库里抽 2~3 条**口吻样本**，接在**整段提示词的最后**（不是第 1 层）。先按这一轮的场景对——用的是**上一轮主模型判的口吻**（`praise / attack / hug` → 哄人 / 被怼 / 被撩三组），它认得反话；没有才退回关键词表。连着两轮不抽同一组；一条都没有时整段不出现。文案里明写"不是台词、别照抄"。放最后是两个原因：它每轮都换，放前面会把后面所有内容一起踢出缓存前缀；放最后又正好吃"近因效应"，越靠近这一轮的输出越影响她怎么说话 |
| 你排好的日程 | 她自己排的事：**几点做什么**、**上次什么时候跑的**（"还没跑过 / 2 小时前"）、**下次什么时候**（"今天 21:30 / 明天 08:00"；一次性日程没有"下次"）。她才知道"今天还有没有事""刚做过什么"，不会把每天的例行当成心血来潮 |
| 还没聊完的 | `他 9 月 29 号要去体检` 这类"他说了一半、还没结果"的事。每条后面括号里带**他说这句话的日期**（"今天说的"/"3 天前说的"），因为句里的「明天 / 下周」是按那天算的，过期了要改问结果；到点且这个人再出现时才出现，附一句"别像查户口"；问两次还没结果就先放下，挂满一周自动丢掉 |
| 你心里搁着的事 | 她自己的心事（`heart_knot`）。**分了人**：跟谁说话就只想谁的那件，跟别人说话时关于那个人的一字不提（自主决策那一路会写成「关于某某」）；没写对谁的就是她自己的事，谁面前都带 |
| 你还记着他一笔账 | 记了账就出现，而且**只对当事人**（回话时最多 1 条，自主决策时最多 2 条）：让他这一档冷下来，提示词里写明"可以淡、可以带刺，但别翻旧账、别每轮提、别跟别人说" |
| 你自己还记着的事 | 她自己答应过 / 想做的（`own_topic`）：只跟相关的人说，注明是哪天记的，提示词里写"想起来了就顺手做掉，别当任务清单念" |
| 说话密度 | 最近一段时间她说的句数超过阈值时，会多一段提醒：「这轮尽量少说话，能只做动作就别开口」 |
| 图片 | 配了 `vision_provider_id` 时：先转述成文字（提示词可在「全局设置 → 图片转述」里改，默认会认出是不是表情包 / 什么梗；描述也会写进聊天留档，后续轮次仍看得到）。转述分两步：**看图**（多模态，**不带话题上下文**——带过之后弱模型会照着话题脑补画面，实测一张表情包被描述成"群聊截图、在争论蘑菇是不是植物"；也因为不带上下文，同一条转述才能安全地跨话题缓存）→ **关系**（纯文本、带当前这句话和最近群聊，只判"这图和话题什么关系"）。没配看图模型时：**直接把图片交给多模态主模型**（自上次回复以来最多「一次最多带几张图」张，含引用消息里的图）。主模型能吃图时，聊天记录里最近「聊天记录最多带几张图」张也会一起发过去，并在记录里标成「（见图1）」（见下文「聊天记录里的图」）。取图走 AstrBot 自己的组件解析，http / 本地文件 / base64 都支持；**取不到地址也会写一条日志**（附协议端给的字段），成功与失败都能在日志里「图片内容」看到 |

**想看完整提示词**：编辑器「调试 → 预览注入内容 / 预览自主提示词」里会给一份**分段索引**
（每段标题 + 字符数）再加上全文——提示词三四千字，索引能让你一眼确认"某一段到底进去没有"。
群里用 `/vw debug autoprompt` 只会回索引和文件路径（完整内容写到
`data/plugin_data/astrbot_plugin_virtual_world/prompt_autonomous.txt`），
因为把几千字直接丢进聊天窗口会被平台截掉尾巴，正好是「群里最近在聊」「你最近说过的话」那几段。

预览输出最前面还会多列一行「状态槽」：那是别的插件留下的状态（今日穿搭、背包…）——
动作里配了「结果记进状态槽」之后，工具 / 指令的结果就留在她那儿，之后每一轮提示词都带着
（持续型动作一拿到结果就记，不必等占位时间结束）。**过期的那条会标出「不会写进提示词」**，
所以"槽里明明有、提示词里却没有"不用再猜。

**非工具型动作也能写槽**：追剧、看书、打游戏这类动作没有工具返回值，内容是**她自己说的**。
配了槽名之后，她事后那句"在重看《海兽之子》，看到鲸鱼那段还是起鸡皮疙瘩"会记进
「在看的剧 / 在读的书」，下一轮提示词里就有——不然每次追剧都像第一次看，只会凭空来一句吐槽。
内置的「追剧」「看书」已经配好了这两个槽。


## 群聊上下文怎么存、怎么带

「保存下来」和「带进提示词」是两件事，配置也分开：

| 层 | 在哪配 | 默认 | 说明 |
| --- | --- | --- | --- |
| 留档 | 全局设置 → 上下文 → 留档保留多少条 | **每个会话** 300 | 存在 `state.db` 里，重启后还在；**按会话各自滚动**——一个热闹的群挤不掉私聊的记录 |
| 携带 | 全局设置 → 上下文 → 每个会话带多少行（还没回过的） | **每个会话** 40 行 | 每轮提示词里带的那一小份。**按"合并后的行"算**：同一个人连着说的几句并成一行（连发十条也只占一行）；合并认的是 QQ 号，昵称 / 群名片变了照样并 |
| 已回过 | 全局设置 → 上下文 → 已回过的那批带多少行 | 40 行 | 「这里刚聊过的（你已经回过话了）」不受时间窗限制，最多带这么多行 |
| 时间窗 | 全局设置 → 上下文 → 多久内算「还热乎」 | 180 分钟 | 只管"还没回过"的那一批：更早的群聊不再原样带进提示词（它可能已经进了压缩摘要）。默认从 60 提到 180——群里聊得快的时候，一小时太短了 |
| 别处 | 全局设置 → 上下文 → 别处同时听到的带多少行 | 12 行 | 「你在别处同时听到的」只当背景，单独一份额度、不占上面那两个 |

留档超出上限时有两种处理：

- **直接丢弃最早的**（默认）：不额外调用模型，最省；
- **压成摘要**：把较早的聊天交给 `context_provider_id` 压成一段摘要，
  摘要会一直跟着提示词，原文只留最近的若干条。压缩在 tick 里发生，
  有「攒到多少条开始压」（默认 200 条，以前是 30/80）「压缩后保留多少条原文」
  「两次压缩至少间隔多久」三个参数控制频率。
  **摘要按会话分开压**：一个会话组里的群和私聊各存各的，提示词里写成
  「更早聊过的（这里）」「更早聊过的（私聊 …）」——以前是一段混着的，分不清哪句是哪儿的。
  老存档里那份全局摘要会挂到存档会话名下，不会丢。

调试时可以在「控制台」页直接点 **清空上下文**（在页面右上角、名片那组按钮的最后）：它会清掉**当前会话**的留档与摘要
（会话组里别的群 / 私聊的内容不动），世界状态、记忆、日程都不受影响；
旁边还有「群聊上下文」面板可以确认当前留档条数和摘要原文。

### 提示词里的群聊分三段

她看到的群聊背景不是一大坨，而是按"有没有回应过"分开的三块：

| 段 | 内容 | 为什么要分 |
| --- | --- | --- |
| 之前的群聊 | 她上一轮已经回应过的那批原文（最多「已回过的那批带多少行」行）+ **她自己写的那句「上一轮你们在聊：」** + 更早的压缩摘要 | 这些再回应一次就重复了；但直接删掉她就会失忆。那句话题背景**每轮都会带**，超过「有效期」就不再当"刚才"用 |
| 最近在聊什么 | **她还没回应过**的原文，带时间（`[21:04] 小明(42): …`）；同一个人连着说的几句合并成一行；图片的转述描述跟着消息一起带进来 | 这才是这一轮真正要接的内容 |
| 你最近说过的话 | 她最近 3 条发出去的话 | 提示她别再用同样的开头和句式 |
| 你在别处同时听到的 | 同一个她在别的群 / 私聊里说的话（会话组才有），只当背景 | 免得她在群里答私聊的问题 |

「已回应水位线」是在**她真的开口之后**才推进的：推进时把她刚刚回应过的那批压成概览，
水位线之后的消息才算"还没回应过"。判断用的是**序号**而不是时间戳——
时间戳只精确到秒，她说完的同一秒里进来的消息会被误判成"已经回应过"。

时间窗（「多久内算还热乎」）只管"还没回应过"的那一批：**她已经回过话的部分不受时间限制**，
会原样列在「这里刚聊过的（这批你已经回过话了）」里——聊过一个小时，她也接得上刚说过的话。

**每条写多少字不一样**（全局设置 → 上下文）：

- 「还没回过」的那批默认每条最多 **500 字**——这是她真正要读、要回的内容，
  以前统一按 100 字掐，长一点的更新公告、群公告到她那儿只剩半句；
- 「已经回过」的那批、以及别处听到的默认每条 **200 字**（只当背景，省 token）；
- 真超上限时会截断，并写清「（这条还有 N 字没显示）」，尽量切在句末——
  只留一个光秃秃的「…」她会以为对方话说到一半（"你倒是说完啊"）；
- 整段聊天记录还有一层**总字数预算**（默认 16000 字）：超了先丢最早的背景
  （已回过的 → 别处的），实在放不下才动"还没回过"的那批，并在那一段写明省了几条。

### 引用了哪一条

群友**引用**一条消息再说话时（「如何评价」+ 引用），引用内容会跟着这条消息一起写进正文：

- 被引用的那条**还在聊天记录里**：只点出开头（`他引用的是上面聊天记录里的那条（不相疑：「2.0更新…」）`），
  让她自己往上对照——不再把原文抄一遍，省 token 也更像人；
- 那条**已经不在聊天记录里**（很久以前、已经掉出留档）：把原文写进来
  （上限「引用旧消息最多写多少字」，默认 1000，超了同样标明还剩多少字）；
- 两种情况都会写明「**这是引用，不是他这次打的字**」——不然她会以为对方话说到一半。

### 谁在跟谁说话（@ 的标注）

群里人多的时候，光看一句「你倒是说啊」分不清是在跟谁说话。每条带 @ 的消息后面会跟一条注释，
把"点到了谁"写清楚：

- `@ 了你（10001）` —— 点的是她。**正文里可能看不到这一下**：AstrBot 会把"开头的 @ 机器人自己"
  从正文里去掉（组件里还在），所以经常出现"正文像是只 @ 了别人、其实先点了她"，
  注释会补上这个事实；
- `；其中 小明(42) 不是在 @ 你（那是在叫别人）` —— 一条消息同时点了她和别人时，写清哪几个不是在叫她；
- 只 @ 了别人时写 `**这些都不是在 @ 你**（那是在叫别人）`，免得她把别人的话揽到自己身上；
- 协议端没解析出昵称时不会写成 `2829449702(2829449702)`，直接给一个号码。

这条注释**不会跟着正文被截断**：正文太长时只掐正文，注释整段留着——它正是"这句冲谁说的"的关键。

**每条消息还会带一个箭头**：收到消息时就把 @ 名单和引用对象结构化存下来，聊天记录里渲染成
`- [16:01] 牛佳晨(3090967184): → @老普机器人：出来干活　（这句是冲别人说的，不是在问你）`；
点的是她就写 `→ 你`，引用她写 `→ 引用 她`。确定不是在跟她说话时会补一句"不是问你"，
不确定就不猜（只写正文）。同一个人的连发合并成一行时，箭头跟着各自那一句走。
另外，回复协议里主模型还要自己填一个 `addressing`（`me` / `others` / `unclear`）：
没有 @ 的一句「你倒是说啊」靠结构化信息看不出来，得靠它判；判成 `others` 时那条消息会被标上，
日志里也写「她判断这句是在跟别人说话」，下一轮渲染就会带提示。

### 注入模式：世界状态写在用户消息那一侧

「注入模式」（不接管回复、只把世界认知喂给主人格）**不再把世界状态追加到 system prompt 的末尾**。
前缀缓存按 token 前缀命中，而世界状态里带着时间、位置、心情、日程、聊天记录，每轮都不一样——
挂在 system prompt 尾巴上等于把分叉点钉在那里，它后面的**整段历史**都再也命中不了缓存。
现在固定不变的那几句说明留在 system prompt，每轮变化的那一大段走 AstrBot 的
`extra_user_content_parts`（会拼进最后那条 user 消息，和引用消息、图片说明同一个位置）。
老版本 AstrBot 没有这个字段时自动退回原来的写法。调试日志里会打一行
`system_prompt 指纹 …（跨轮应保持不变）`，可以直接核对前缀有没有被改。

留档顶到上限时，如果选的是「压成摘要」，被顶掉的那几条会先攒着、等下一次压缩一起并进摘要
（聊得快的时候也不会凭空丢记忆）；选「直接丢弃」的话，日志页会提醒一次并说明怎么改成压缩。

### 聊天记录里的图

群里发的图会跟着消息一起进聊天留档（同一条最多记 2 张、超长的 base64 不存）。
主模型能吃图时（全局设置 → 上下文 → 聊天记录里的图）：

- **自动**（默认）：读 AstrBot 里这个 Provider 勾选的模态，勾了图像就直接发；读不到就不发；
- **总是发**：不检测，确认自己的主模型能吃图时用；
- **只发描述**：图只以转述文字的形式出现。

发过去的那几张会在聊天记录里标成「（见图1）」「（见图2）」，编号按时间排（图1 是最早的那张），
和附件里的顺序一一对应；其余的图仍然只有文字描述。这样她"看图"和"看记录"能对上，
而不是对着一张表情包猜群里在说什么。

**转述只转"不给她看的那几张"，而且收到图的时候就转。** 一次回复里最多直接带
`一次最多带几张图` 张（默认 3）给主模型，超出上限的**先来的旧图**在**收到新图的那一刻**
就转述成文字（第 4 张一到就把第 1 张转掉，不等她回话）；主模型看不见图时，
这一轮该她看的图一起打包转述。所以：

- 只发一张图时不会多花一次转述——那张图本来就交给主模型看；
- 连着发到第 4 张，最早那张才被转成文字，最新的 3 张照旧发图；
- 同一张图转过一次就不再转第二遍，转述结果挂回**它自己那条**聊天记录（不会串到最新那条消息上）。

@ 的记录也在这里：消息里 @ 了谁会被写成 `他(QQ号)`，@ 到她自己的会标成 `你（名字(QQ号)）`——
她并不知道自己的 QQ 号，不标出来就分不清那是不是在叫她。

图片转述会连同**当前消息、引用的消息、最近几句群聊**一起交给多模态模型，
输出「画面描述｜类型｜与话题的关系」，所以同一张图在不同话题下会得到不同的描述。
其中「类型」就是**表情包识别**：默认提示词要求它先判断这是不是表情包 / 梗图、是什么梗、什么情绪，
因为接一张梗图和接一张照片的方式完全不同。这段提示词在「全局设置 → 图片转述」里可以改，
留空就用内置默认；转述模型看不到群聊，所以要在提示词里把「描述里必须包含什么」交代清楚。

### 同一张图只识别一次

表情包、梗图在群里会反复出现，所以转述结果是**按图片指纹缓存**的（默认开，在「全局设置 → 图片转述」里可关）：

- 指纹来自图片内容本身：协议端给的 `base64` 直接对内容算摘要，http 链接只取路径——
  同一个文件换个带 token 的临时链接也能认出来；
- 缓存写在 `state.db` 里，**重启插件后仍然有效**；默认最多 500 张、保留 30 天，按最近使用淘汰；
- 命中时只复用「画面描述｜类型」这半句，**「与话题的关系」不会跟着复用**——
  换个话题发同一张表情包，关系由主模型看当前上下文自己判断，不会拿着上一轮的结论硬套；
- 识别失败**不写缓存**（偶发超时不该被永久记成"看不出"），60 秒内也不重复重试；
- 同一张图在两条消息里同时出现时，只会识别一次，第二条等第一条的结果。

省下多少次识别可以在同一块里看到（"已记住 N 张图，累计省下 M 次识别"）。


## Token 预算

自主行为默认很省：模板动作不调 LLM，一次 LLM 计划覆盖 30 分钟（`plan_valid_duration`），
并且有四道闸门防止空群里"自言自语烧 token"：

| 配置 | 默认 | 作用 |
| --- | --- | --- |
| `limits.llm_plan_min_interval_seconds` | 900 | 两次「问 LLM 要计划」之间至少隔 15 分钟 |
| `limits.max_llm_plan_per_hour` | 4 | 每小时最多 4 次 LLM 计划决策 |
| `limits.max_llm_text_per_hour` | 20 | 每小时最多 20 次 LLM 生成发言，超出后她这一轮保持安静（不再退到写死的通用台词） |
| `limits.max_arrival_decisions_per_hour` | 12 | 每小时最多 12 次「走到新地方就地决策」；这类决策不占自主行动额度，单独限流 |
| `limits.forced_plan_min_interval_seconds` | 3600 | 极端保护（强制睡觉/找人）最短触发间隔 |

注意：**接管回复**每条消息都要跑一次完整的五层提示词，这是这个插件最大的 token 开销来源；
如果只想要"她知道自己在哪"这层认知，把回复方式切回「仅注入状态」会便宜很多。

### 提示词分层与前缀缓存

五层的顺序是**按"越稳定越靠前"**排的，这样前面那截可以整个会话复用，吃到 provider 的前缀缓存：

| 层 | 内容 | 变化频率 |
| --- | --- | --- |
| 第 1 层 | 人设 | 不变 |
| 第 2 层 | 世界规则 | 不变 |
| 第 3 层 | 输出格式（JSON 契约、字段说明、通用规则） | 不变 |
| 第 4 层 | 当前场景：**你自己的本事**（内置动作，到哪儿都在，内容基本不变）→ **这个地方能做的事**（按地点变）→ 可达表 | 换地点时变 |
| 第 5 层 | 运行时状态（数值、记忆、群聊上下文…） | 每次调用都变 |

所以能命中的前缀是**前 3 层**（默认配置下约 1.7k 字符），而不是只有前 2 层。
为此做了两件事：

- 能把哪些 `type` 是随地点变的，所以**不放在固定的第 3 层**，而是放在第 4 层；
  第 3 层里不出现任何地点名、动作 id，改地图也不会把缓存打散。
- 第 4 层内部再分两块：**内置动作（说话 / 回想 / 记住 / 移动 / 日程这类，在任何地点都一样）
  单列成「你自己的本事」放在前面**，剩下的才是「这个地方能做的事」。前一块基本不变，
  也更容易被她想起来——不然几十条地点动作混在一起，回想 / 记住这种最该用的反而容易被淹掉。
- 「问计划」和「生成回复」共用第 1、2 层——两种调用能吃到同一段前缀。

代价是"格式要求在提示词中间"会稍微削弱它的存在感，所以最末尾补了一段三行的
「最后确认」当近因锚点：只输出 JSON、reasoning 写在前面、别重复最近说过的话。
**声音样例排在整段提示词的最后一节**（在「最后确认」之后），一样是为了吃到近因效应。

> 缓存是否生效取决于 provider：DeepSeek / OpenAI 这类服务对相同前缀自动降价（通常要求前缀
> 达到一定长度），本地部署或不做缓存的 provider 则没有区别。想让缓存更值，别把易变内容
> 写进人设或世界规则里。
