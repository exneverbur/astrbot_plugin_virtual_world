# 常见问题

[文档目录](README.md) · [按主题拆开的详细说明](GUIDE.md) · [返回 README](../README.md)

不回话、不触发、刷屏、报错这类情况的排查。

## 常见问题

**她完全不动？** 检查会话是否在白名单里（`/vw session add`）、插件是否启用、
`tick_interval` 是否过大。用 `/vw debug state` 看 `world_time` 有没有涨。

**改完配置要手动热加载吗？** 不用。编辑器右上角只有「保存」，保存成功会**自动热加载**并提示
「已保存并生效」。唯一例外是 AstrBot 插件配置页那一份（Provider、tick 间隔、密码…），
那份改动要在 AstrBot 那边点热加载或重启才生效。

**保存报错了怎么办？** 提示会说明是哪一份配置、哪一项没过校验（例：
「日程没通过校验…schedules / 0 / time：时间超出范围」），改动还在编辑器里，改完再存一次即可。
手写 JSON 里混进 `null` 或空串这类脏值不会让整份配置存不下去——`list[str]` 字段读入时会自动洗干净。

**她一直在说话 / 从不说主动话？** 调整 `limits.max_autonomous_per_hour` 与
`limits.max_share_per_hour`；`decider_interval` 决定她多久评估一次；
「孤独感与插话」里的阈值和冷却决定她多爱接话；无人回应保护会让她安静下来。

**她睡着的时候还在群里聊天？** 看「睡眠与打断 → 睡觉时被叫怎么办」是不是被改成了「照常回复」，
以及唤醒词是不是写得太宽（比如把「早」也加进去，那她每天都会被正常问候叫醒）。
她睡着时的判定只认「@ 她 + 唤醒词」，两条都不满足才走固定文案。

**后台一直报「发送消息失败 / Timeout: NTEvent …sendMsg」？** 这是 QQ 协议端（NapCat/Lagrange）
没等到 QQ 客户端内核确认，属于平台侧问题（协议端掉线、客户端卡死、被风控或禁言）。
插件这边**失败就失败，不会重发**：

- 同一个会话发送失败后进入 **180 秒冷却**，期间连平台都不碰（避免把更多消息塞进协议端队列，
  恢复后一次性喷出来）；冷却期内同一批剩下的消息也不再尝试；
- 接管回复同样只发一次——以前"失败就换一条通道再发一遍"的兜底已经去掉，
  因为超时经常是"其实已经发出去了"，补发就变成刷屏；
- 失败会记一条 `send_failed` 事件（日志页能看到"这条没能发出去（原因）：内容"），
  后台日志每个冷却窗口只打一条，不会刷屏。

**群名片一直报错？** 失败会按 5 分钟起、逐次翻倍退避（最多 1 小时一次），
成功或状态变化后重置，不会再每分钟重试一次。

**@ 她没反应？** 先看编辑器日志页有没有「接管失败」条目，再看后台日志的「接管没生效」；
常见原因是没配 Provider、模型返回的不是 JSON、或模型没给出任何动作。
这几种情况下她都保持安静（不会换成主人格来答），所以排查要看日志而不是等回落。

**模型把思考（thinking）也吐出来了，甚至发到群里？** 有些模型 / Provider 不认
「关闭思考」这类参数，偶尔还会漏掉开标签、只留一个 `</thinking>`。插件在解析前会先剥掉
`<thinking>…</thinking>`、`</thinking>`、```` ```thinking ```` 这几种残留，再去找 JSON：

- 剥完之后是合法 JSON → 正常执行，思考一个字都不会进群；
- 剥完之后只剩长文 / 半个 JSON → **什么都不发**（只记一条警告），不会把思考当发言糊到群里；
- 剥完之后是一句短话 → 按"她直接说了句话"发出去（这是模型没走 JSON 协议时的老兜底）。

想在日志里核对，看那条 `reply` 事件的 `raw`（模型原话）和 `warnings` 就行。
要彻底不思考，得换一个听话的模型或 Provider——插件这边只能容错，不能替模型闭嘴。

**工具动作没反应？** 确认动作里选的工具在 AstrBot 里真的注册了（`/vw tools` 可以看当前能用的工具）；
工具调用需要该会话最近有过消息事件（插件会用最近一次事件作为调用上下文）。

**群名片不变？** 发送 `/vw nickname`（不带参数）会直接告诉你现在的情况：
原名是什么、当前名片是什么、按当前状态应该显示什么、有没有被锁定、冷却多久。
编辑器「实时状态」里的名片一栏只有一个「锁定 / 解锁」按钮，按钮文字就是当前状态的下一步操作
（锁定中会显示「解锁」，并且按钮变亮），旁边是「保存名片」和「恢复原名」。

名片按这个顺序算：`原名 | 状态文案`。
**原名**依次取「插件抓到的她当前群名片」→「全局设置里的 Bot 名称」——
全新安装时第一条要等群里有过消息才能抓到，所以建议先在「全局设置 → 基础 → Bot 名称」里填一个名字。
**状态文案**来自「全局设置 → 群名片同步」里的「状态 → 名片文案」和「地点 → 名片文案」，
两边都没配就会保持原名不动。

改名片失败时不再静默：日志页会出现一条「群名片」事件，写明原因，常见的是——
当前平台不支持（只有 aiocqhttp 系的 OneBot 实现提供 `set_group_card`）、
私聊没有群名片、机器人不是群管理/群主被协议端拒绝、或者还没收到过这个群的消息（拿不到机器人句柄）。
想手动接管可以用 `/vw nickname lock`，手动指定用 `/vw nickname set <文本>`。

**为什么不用向量检索记忆？** 记忆始终绑定在「会话 + 人格 + 地点 + 人」上，
召回范围很小且过滤维度是结构化的，SQL 更精确也更省开销。
