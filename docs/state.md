# 状态与情绪

[文档目录](README.md) · [按主题拆开的详细说明](GUIDE.md) · [返回 README](../README.md)

五个数值、情绪两轴、没人理她时会怎么样。

## 数值与状态

内部状态：`energy` `loneliness` `curiosity` `affect`(心潮) `valence`(效价) `boredom` `desire`(欲求) + `mood`，
七个数值都真实驱动行为：

| 数值 | 谁在用 |
| --- | --- |
| 精力 energy | 决策器（<0.25 该休息：夜里睡整觉、白天先小睡）、日程条件 `min_energy`、动作前置条件、睡觉恢复、极端保护（连续 3 天 <0.1 强制补觉，白天也是先眯一会儿） |
| 孤独感 loneliness | 决策器（>0.7 去大厅找人）、日程条件、极端保护（24h >0.9 强制找人） |
| 好奇心 curiosity | 决策器（>0.7 且在书房且有搜索工具 → 去上网）、查完东西回落、睡觉时回落 |
| 心潮 affect | 情绪被激起的强度（不是开心程度）：和效价一起决定**心情词**和**这一轮的表达方式**、给记忆权重加成；被夸/被抱/吵架/被冷落都会推高它，之后自然回落到「静止位置」。**有边际递减**，见下 |
| 效价 valence | 心情的好坏（0.5 是中性）：由 `基线 + 短期偏移` 组成。基线跟精力/孤独/无聊/好奇与时段走（本身不存历史），偏移由事件产生、随时间归零。它决定"情绪朝哪个方向"，也决定插话的难度 |
| 无聊 boredom | 决策器（>0.8 换地方、>0.45 去看书）、看书/做饭降低 |
| mood | 由**情绪两轴**派生（心情词），精力低时加「困倦」修饰；动作也能临时覆盖（`mood:满足`） |
| 欲求 desire | 想被**实实在在地碰一下**（摸摸头、抱抱、亲亲）：没人碰就慢慢涨（默认约三天攒满，累了或心情差时涨得慢），被亲近的动作满足、被撩会往上跳；睡着时回落。>0.85 时心情词会多一个「想贴着人」修饰，>0.7 时「找人」这条决策分支权重抬高。**它管的是身体接触，跟孤独感（想有人说话）是两回事** |

**「亲近一下」算不算数，是怎么判的**（三层，从确定到不确定）：

1. 动作自己在编辑器里填了**「亲密程度」**→ 就用他填的（0 表示"这不算肢体接触"）；
2. 内置动作 → 查对照表（抱抱 / 亲亲 1.0、依偎 0.9、蹭蹭 / 靠肩膀 0.8、摸摸头 / 十指相扣 0.7、
   牵手 / 闭上眼 / 揉肩 0.6、披外套 / 喂一口 0.5、捏脸 / 咬手腕 / 擦眼泪 0.4、拍肩 0.2、击掌 0.1）
   ——不花任何调用；
3. **用户自己新加的动作** → 交给便宜模型判一次（跟"能不能走安抚通道"共用同一份判断，
   结果按"动作名字 + 说明"的指纹缓存；改了名字或说明才会重判）。

所以后加的动作不用配也能工作，想精确控制就填那一栏。批量生成动作时模型也会一起给出这一项。

**欲求高了她会自己想去贴——而且这件事交给她自己决定。** 欲求 × 当天基调里「贴一下」那一条的权重
过了 `desire_push_threshold`（默认 0.75）时，插件会**把这一轮交给大模型**，提示词里给三样东西：

- **现在什么状态**（欲求多少、心情、在哪、这会儿在做什么）；
- **能找谁**——`user_presence` 里最近还在说话的人，**按好感从高到低排**，每个人带上关系档、
  这一档明确不许的动作、以及今天还剩几次主动找他的额度；
- **能做哪些肢体接触**——此刻这个地点能做的那些动作，附上各自的「亲密程度」（0~1）。

然后**由她自己决定**：去哪儿说（计划里写 `send_to`：想私密就发私聊、想让别人看见就发群）、
做什么、对谁做；**什么都不想做也行**，写个别的计划就好。装了带提示词层的扩展时，
这一轮还会把扩展那一层一起带上——她决定的时候得看得见扩展自己的那些数值。

频率有限制：`desire_push_daily_max`（默认一天 3 次）、`desire_push_min_interval_minutes`
（默认两次至少隔 40 分钟），整个会话组算一份。基调也参与：黏人的日子更容易"想要"，想独处的日子几乎不会。

### 今天的基调：每天掷一次

换天（或一觉睡醒）时掷一次**今天的调子**，一天只掷一次，她不会主动解释这件事，但那一整天
各条曲线走得快慢确实不一样。它**不改性格、不改数值本身**，只给这几条速率乘一个倍率：

| 基调 | 权重 | 感觉上是什么样 |
| --- | --- | --- |
| 平静 | 26% | 跟平常没两样（也是默认的多数日子） |
| 懒散 | 18% | 精力掉得慢、不太想知道新东西、坐得住、容易发呆 |
| 活跃 | 16% | 想知道新鲜事、容易被逗起来，玩久了也累得快 |
| 黏人 | 15% | 一个人待着更容易发闷、想念涨得快，情绪也挂得久 |
| 想独处 | 15% | 孤独涨得慢，倒是有心思鼓捣点自己的事 |
| 说不上来 | 10% | 心里有点说不清的毛躁——见下面「模糊档」 |

它调的是精力衰减、孤独增长、好奇增长、无聊增长、心潮回落、效价回落这六条（每条约 0.6~1.5 倍）。

**基调还会拨决策分支的权重。** 数值只决定"哪件事够格了"；几件事同时够格时，
谁被挑中由权重决定（权重一样就退回原来的固定优先级，不掷骰子）：
黏人的日子「找人」权重 ×2，懒散的日子「上网查东西」×0.55、「看书」×1.3，
活跃的日子「上网」×1.5、「换地方」×1.4，想独处的日子「找人」×0.45。
所以同一天里她做的事，会跟昨天明显不是同一个套路。

「全局设置 → 状态变化速度 → 今天的基调」里可以整个关掉，或者把**作用强度**调到 0~1
（0 = 照样掷、控制台照样显示，但完全不影响数值）。控制台的状态栏、日志里的「今天的调子」、
以及提示词里都写着今天掷到了哪一种——不然"她今天怎么怪怪的"只能靠猜。

### 模糊档：说不清是什么感觉

掷到「说不上来」的那些天，心情词会多一档**模糊档**：本来写着"说不上好坏"的那几格
（`心潮起伏` / `上头` / `激动`）换成 `说不上来 / 心浮 / 没由来的烦 / 空落落 / 提不起劲 / 有点飘`
里的一个（同一天固定用同一个，不会来回换）。

说得清的格子不受影响——`平静` 就是平静，`来劲` 就是来劲，`气炸` 不会变成"说不上来"。
这一档想说的是：真人很多时候**确实讲不清自己现在是什么感觉**，不是每一种情绪都有名字。

### 好奇心：会涨，也会被满足

好奇心是**唯一一个"没有别人参与也会涨"的探索欲**（默认 1.44/天），所以它必须同时有两条下落的路，
否则一天下来必然钉死在满值，表现就是"一整天反复跑去上网查东西"：

- **查完就满足**：检索型动作（`tool_flow = search`，内置「上网搜索」就是）**真拿到结果**之后，
  好奇心按动作里的「查完回落多少好奇」降一次（默认 0.3）。这一刀是专门用来把她压回 0.7 以下的——
  动作自己配的那点 `curiosity: -0.06` 只够抵消一小时的自然增长，压不到阈值以下，
  结果就是冷却一到又去查同一件事。什么都没查到（没配检索工具、工具报错）不算满足，不回落。
- **睡一觉会放下**：睡觉 / 小睡期间好奇心按「睡觉时好奇回落/分钟」（默认 0.0012）往下走，
  但不会低于「睡醒时最低的好奇」（默认 0.3）。以前睡眠是把数值**冻结**的，
  于是她会带着白天攒的满格好奇心入睡、醒来第一件事就是冲去查东西。
- **越接近满值涨得越慢**：过了 0.7 之后增长速度按剩余空间递减（到 1.0 时系数归零），
  所以它是渐近贴近满值，而不是一整天顶死在那里。

这三条都在「全局设置 → 状态变化速度」里，检索那条在动作编辑器的「检索设置」里。

### 情绪两轴：心潮 × 效价

心潮（唤醒度）和效价（方向）是两个独立的轴：**心潮控制她有多激动，效价控制她激动成什么样**。
两轴各分五档（很低 / 偏低 / 中 / 偏高 / 很高），交叉出 **25 种表达形态**：
同一个格子同时给出心情词和这一轮的说话约束，所以"微微开心"和"开心到冒泡"不再是一句话。

| 心潮 | 效价很低 | 效价偏低 | 一般 | 偏好 | 很好 |
| --- | --- | --- | --- | --- | --- |
| 很低 | 沉郁 | 淡淡的 | 恬静 | 安稳 | 舒坦 |
| 偏低 | 低落 | 有点闷 | 平静 | 轻松 | 愉悦 |
| 中 | 不痛快 | 心浮 | 心潮起伏 | 轻快 | 雀跃 |
| 偏高 | 恼火 | 烦躁 | 上头 | 来劲 | 兴冲冲 |
| 很高 | 气炸 | 憋着火 | 激动 | 兴奋 | 欢呼雀跃 |

格子之外还有两层补充：

- **修饰**：别的维度也明显时叠一个词——`困倦 ·`（精力低）、`想找人 / 有点被晾着 ·`（孤独高）、
  `闲得发慌 ·`（无聊高）、`心痒 ·`（好奇高）。同一个"兴奋"，配上不同修饰就完全不是一种情形。
- **来源**：最近一次让情绪明显变动的**原因**会记下来，标签写成
  `兴奋（因为：被哄了一下）`、`憋着火（因为：你说了话没人接）`；超过 30 分钟自动不再挂。

这几条约束是**硬上限**：群聊里最多 2 条、私聊最多 3 条，并且和「说话密度提醒」冲突时取更严格的一条。
关掉「全局设置 → 说话节奏 → 让心情影响这一轮的说话形态」就回到纯人设风格。

**情绪也会推着她主动**：心情好时「主动接话」的门槛会往下走一点（最多 −0.05），
「开口意愿」的公式里也算了效价（按离中性多远算，不会把整体意愿抬起来）；
心情差时反过来——阈值上浮，长期低落还会暂时关掉「想被注意到」这条动机。

两条时间规律：**事件只负责拉高，不负责维持**（脉冲当场生效，之后按真实时间回落到基线，
和 tick 长度无关）；**基线只跟五维与时时段有关**（本身不存历史，所以"最近心情一直不好"需要慢慢积累）。

### 安全阀

效价长期偏低（<0.25 持续 30 分钟）会做两件事：

1. 把效价偏移**减半**（拉回基线，而不是硬设一个好心情）；
2. 让自我调节类的动作更容易被选中（发呆 / 去看书的门槛下调），并给她一句
   「你现在更想自己待会儿」——这是行为倾向，不是被安排一个动作。

另外效价 <0.2 持续 30 分钟会关掉「想被注意到」那条插话动机，且至少关 15 分钟
（避免阈值边上反复抖）。「想发作」那条不受影响：被惹毛的人反而是想开口的。

另外这些数值都会：每 tick 自然演化、被地点氛围调制、被事件（被 @、被抱、群冷清…）和动作效果改变、

### 心潮的边际递减

心潮是「情绪被激起的强度」，所以**不是线性叠加**的：越高的时候，同样的刺激能加进去的越少
（最低保留 10% 效力）。这样普通闲聊只会让她有一点起伏，要真正「难以平静」得靠亲密或强烈的互动。

配合两条调整：普通消息的加成从 `+0.08` 降到 `+0.02`（被 @ 时 `+0.06`），回落速度从
`0.012/分钟` 提到 `0.02/分钟`。模拟一个很活跃的群（每分钟约 1 条消息、20 分钟夸她一次）两小时：

| 时间 | 旧规则 | 现在 |
| --- | --- | --- |
| 10 分钟 | 0.88（直接顶到「难以平静」） | 0.37 |
| 60 分钟 | 0.88 | 0.53 |
| 120 分钟 | 0.88 | 0.56（心潮起伏） |

想让情绪更敏感或更迟钝，调「状态变化速度 → 心潮回落/分钟」，以及动作里的心潮效果。
并写进提示词——所以数值不是装饰，而是真的在决定下一步做什么。

### 情绪量程：为什么"撩两句"不会再把她顶满

效价那一侧还有三道闸，它们合起来决定「100 分意味着什么」：

| 闸 | 默认 | 作用 |
| --- | --- | --- |
| 聊天单轮上限 `chat_valence_cap` | 0.05 | 一轮对话最多推动效价多少。她说得再好听，一轮也只值这么多 |
| 聊天每日额度 `chat_valence_daily_cap` | 0.15 | 一天里聊天累计最多推多少（正负各算一份）。超了就不再推 |
| 连着被哄会麻木 | 1.0 → 0.6 → 0.35 → 0.2 → 0.12 → 0.08 | 「被叫 / 被夸 / 被哄」连着来，幅度递减；隔 20 分钟重新算 |

两道额度是**所有聊天路径共用**的：主模型给的 `valence_delta`、关键词兜底的「被夸 / 被哄」，
都从同一份额度里扣——不然总有一条路能绕过去。负面不受额度限制（难过不因为今天已经被怼过就不算数），
她真经历一件事（事件系统）也不受限制，那是她生活里的分量。

**难听的话有多难听，看是谁说的**：主模型判出来的负面口吻（`tone=attack`，关键词表兜底也一样）
会按**亲密度**缩放——路人怼她一句几乎不往心里去，亲近的人说一句顶别人几句。
七档下的倍率大约是：

| 她的生效档位 | 敌意 | 冷淡 | 客气（陌生人 / 群友） | 熟人 | 朋友 | 亲近 | 特别的人 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 倍率 | 0.20 | 0.27 | **0.42** | 0.63 | 0.88 | 1.17 | **1.50** |

（没建过档的纯路人是 0.20。正面口吻**不**缩放：那几条本来就压得很小、还带"连着被哄会麻木"，
再按亲密度放大，熟人一句夸奖就能把她顶满。）

**分成两套数是有意的**：日常陪伴涨的是**好感度**（长期关系），不是效价的量程。
她心情的明显起伏应该来自真的经历——事件、约定、惊喜、吵架，而不是几句夸奖。
所以「100」只留给真的极端时刻，日常聊天推到 0.7 左右就是上限。

**他说停就是停。** 口吻表里除了夸 / 哄 / 安慰 / 怼，还有一种是 `refuse`：**他明确叫停或拒绝**
（「停下」「别这样」「不要」「今天不想」）。它**不产生情绪脉冲**，也不当成欲拒还迎——
判出来之后，那一轮按"她去收手"处理，日志里的 `tone` 一眼能看到。
挂了扩展时，扩展还会据此把这件事记成边界（细节看扩展自己那一页的说明）。

调法：觉得她太容易被逗开心就调小 `chat_valence_cap`；想让她日常情绪更迟钝就调小每日额度；
觉得她"记仇太久"再动「效价回落/分钟」（默认 0.01 ≈ 一小时出头回落一半）。

### 安抚通道：她真的难过时，另一条路

上面的每日额度管的是"日常"，可她真的低落一整天的时候，光靠聊天那 0.15 是哄不回来的。
所以另开了一条**安抚通道**：

| 走这条路的 | 触发条件 | 效果 |
| --- | --- | --- |
| 被安抚 `soothed` | 效价低于 **0.38**、对方这一轮的口吻是 `hug`（哄她），或她自己贴过来（抱、亲、靠这类亲密动作） | 效价 +0.10（再乘边际递减与两轴耦合），**不占**当天的聊天额度 |
| 被理解 `understood` | 口吻是 `comfort`（他接住了她说的难受）**且**她确实在难受（效价偏低 / 心里搁着事 / 正在记他的账） | 效价 +0.12、孤独 −0.12，同样不占额度 |

限流不是额度而是**次数**：一小时最多 3 次、每天最多 6 次；「被理解」一天最多 3 次。
一点都没推动（比如效价已经贴顶）就不记次数。这样"连着哄十次"和"哄一次"仍然有区别，
但也不会变成免费回血。

她自己做的动作算不算"亲密"，优先看效果（冲着某个人、降孤独或抬心潮就算），
看不出来的用户自定义动作让便宜模型判一次，判完缓存在库里（不进世界配置），不会每轮都问。


## 无人回应保护

主动发言后会等待 `silence_window_minutes`；没人回应就累加 `unanswered_count`，
达到阈值进入冷却（`cooldown_after_unanswered` 分钟），冷却期间不主动发言，
冷却结束后计数减半。

计数 > 0 时会写进**用户提示词**（不是塞在系统提示词末尾），紧跟"接下来做什么"：
「你最近连续 N 次主动说话都没人回应，你有点犹豫」，并写明默认倾向——
**没人接的时候，下一轮大概率就别追着说了**，真想继续说就说自己身上发生的事。
自主开口和被动回复共用同一套措辞分寸：别吆喝、别招揽、别讨好，想不出什么就保持安静。

另外两处跟"没人理"有关的改动：

- 她**开口求助之后没人接**，那句自我圆场（"算了，我自己来"）交给模型按人设现写，
  写不出来就不说——以前是代码里三句固定台词，谁的人设都会突然冒出一句"本小姐"。
  开关在「没有人理她时怎么办 → 她求助没人接时，补一句自我圆场」。
- **LLM 预算用完之后她保持安静**，不再退到一句写死的通用台词。所以每小时预算给得比较宽
  （被动回复 200、自主发言 20、自主行为 6），真撞上限时宁可这一轮不说话。


## 孤独感与插话

**孤独感（`loneliness`）负责"她想不想找人说话"，心潮 + 效价负责"她说话成什么样"**——
这两件事以前都由社交欲兼着，阈值各自调很容易互相打架，后来拆开了。

系统会保存最近一段时间的群聊内容
（默认时间窗 20 分钟、最多 12 条，按时间自动过期），群里最近确实有人在聊
（窗口内消息数 ≥ `min_messages_to_interject`，默认 2 条）时，**下面两条动机满足一条**就会想开口：

| 动机 | 条件 | 说出来是什么样 |
| --- | --- | --- |
| A 想被注意到 | 孤独感 ≥ **浮动阈值**，且效价 > 0.35 | 由风格格决定；心情差时会更短 |
| B 想发作 | 心潮 ≥ 0.6，且效价 < 0.35 | 通常一条短句，或者干脆只戳一下 |

**阈值是浮动的**（不是浮动意愿值）：心情越差越难开口，最多 +0.10；效价 <0.2 持续 30 分钟会再抬到
+0.15 并关掉动机 A（至少关 15 分钟）。开口之后的形态仍归风格格管，两件事不混在一起。

另外还要同时满足：

- 距离上次插话超过 `interject_cooldown_minutes`（默认 20 分钟）；
- 没在无人回应冷却里，也没超每小时自主上限；
- 没处在"刚回过话"的主动发言冷却里。

插话文案由大模型根据「最近群里在聊」的上下文现场生成；如果她说不出什么就保持安静，不会硬凑。
总开关和这组参数都在「全局设置 → 孤独感与插话」里。

**想知道是谁在限流**：控制台页的「互动与运行」里会显示本小时的插话统计
（想插话几次、被插话冷却 / 无人回应 / 回复后冷却 / 每小时上限分别拦下几次）——
光看频率数字看不出瓶颈在哪，这几个计数才能说明问题。

隐私：只保存最近 N 条、按时间自动过期；命中内容安全屏蔽词的消息不会记录。


## 推理草稿 reasoning

开启后（默认开），大模型在给出动作之前必须先写一段草稿：

```json
{
  "reasoning": {
    "env": "书房，桌上摊着书",
    "state": "刚醒不久，精力一般",
    "mood": "平静",
    "who": "小明在问我周末怎么安排",
    "intent": "随口应一句，然后去泡杯茶"
  },
  "actions": [ { "type": "say", "messages": ["周末啊……还没想好"] } ]
}
```

- **顺序即推理**：模型是一个 token 一个 token 生成的，`reasoning` 写在前面，它的 token 就成了后面
  `actions` 的上下文——这才是真正的"先想后说"。
- **草稿永远不外发**：不进群聊、不计入动作数量、不写进记忆，只记在事件日志里，方便排查"她为什么这么回"。
- **强制读上下文**：让她复述"我在哪、什么状态、什么心情、在和谁说话"，能明显减少
  "提示词说在书房、回复却在厨房"这类低级错误。
- 服务端会**强制把 `think` 动作排到最前面**，不依赖模型给出的顺序；模型没写 `reasoning` 时只告警，不会失败。

推理草稿会让每轮多输出几十个 token，觉得费可以在「全局设置 → 基础」里关掉。
`actions` 里的 `think` 是另一回事——那是真正想留下的内心话，会写进内心记忆。
