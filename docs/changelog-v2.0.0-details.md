# v2.0.0 明细

> **导航与页面名（后一次改版）**：编辑器现在是左侧分组导航（观察 / 编辑 / 配置）共 12 页。
> 本文里的「实时状态 / 状态页」＝现在的**控制台**；事件相关面板已拆到独立的**事件**页；
> 原始事件流收在**日志**页底部。历史描述按当时的样子保留。

[更新日志](../CHANGELOG.md) 里只列了重点，这里是 2.0 全部 81 条改动，
按当初改的顺序排：每条都写清楚"改了什么、为什么这么改"。

### 1. 随机事件系统与能力值

- 她会自己遇上事（做饭糊了、打游戏卡关、被人跟着…），一格一格走：自己拿主意 → 掷骰判定 →
  写结果 → 有伏笔接着演。微 / 小 / 大三档频率、题材与权重都能配；每一件都按她此刻所在的地点
  和状态**临场生成**（没有一个写死的事件池）。
- 能力值（体力 / 智力 / 灵巧 / 心性）只由事件结果改变；判定是「能力值 × 情境修正 × 难度」，
  四档结果，日志里有算式；结果会带一点情绪。
- 需要拿主意时她**开口求助**（那两句由她自己的口吻现写），等待分「活跃等待 / 轻等待 / 自己收尾」，
  等待期间照常聊天；群友的回应只丢掉完全无关的。
- 事件里可以**先去做点什么**再决定（收集信息 / 直接拿主意两态）；同一时间只演一件事；
  每一幕推进 / 完结时按概率拍张图；有伏笔的隔一阵再续演，隔太久自动收尾。
- 配套：日程闸门（她正忙事件时睡觉 / 换地方交给她自己决定，标记"危险"的事件直接让路）、
  事件进行中群名片显示「事件中」、`/vw event` 投递事件、事件可配置分享策略。

### 2. 编辑器界面

- 全局设置按用途分成 6 个横向标签，带设置搜索与「未保存」标记；所有「选会话」的地方
  统一改成选**会话 / 会话组**。
- 状态页重做：能力值**雷达图**、当前事件可直接「立即推进一幕 / 立刻完结」、
  历史事件弹窗能展开看每次明细，并配了一套入场 / 悬停 / 弹窗动画。
  （这套事件面板现在是独立的「**事件**」页；这台页现在的名字叫「控制台」。）
- 预设页新增「**新建默认预设**」（把内置默认世界存成一份新预设，不动当前配置）；
  预设 JSON 除了整段查看，还能**按分区看 / 改**：只看地图、只看动作、只看世界设置、只看日程、只看会话。
- 修掉保存与脏值问题：落点写进 `null` 导致整份保存失败、配置里混进空串、
  校验失败只给英文报错。

### 3. 日志与调试输出

- 调试输出改成**每个类型各自设置**「关 / 完整 / 精简」，新增「事件与线索」「联网搜索」
  「收到消息」三类。
- 日志标明每件事**发生在哪个会话**（私聊里发生的那几行回显也发到私聊）；
  掷骰写明「要掷到 ≤ X，掷出 Y」。

### 4. 睡眠与作息

- 夜晚时段可配（默认 23:00–07:00）：非夜晚不提供「睡觉」动作，熬夜时精力衰减 ×1.5。
- 精力低不再直接睡 8 小时：**夜里睡整觉、白天先小睡**，睡多久按她的说法与配置夹住。
- 睡着时事件照演但不出声；没被明确叫醒就只回固定文案，不调模型、也不交给主人格。
- **被吵醒**：睡着时被刷屏或反复点名，她会迷糊醒一次、只回一两句（可以带起床气、偶尔打错字），
  然后接着睡**同一段**觉——不重新计时、不重复整理、也不给"刚被叫醒"那段保护期；一段睡眠最多一次，扣固定精力。
- **起床气**：睡满整觉是清爽；没睡够、或者中途被吵醒过，醒来会带一段起床气（效价降、心潮涨、说话更短），
  数值与时长都能配。

### 5. 出图相关的内置动作

- 新增自拍 / 拍照 / 拍腿 / 换一套衣服 / 录视频五个内置动作（默认停用），
  每个动作都能配每天 / 每周 / 每月的使用次数上限。
- 生图类动作改成"**当场出图 + 剩余时间占位**"，图片不会落在那句续说后面；
  工具 / 指令出的图会发到群里（多张放同一条）。
- 图片转述省调用：要交给主模型看的那几张不转述，只有被上限挤掉的旧图才转述
  （收到那一刻就转，同一张图只转一次）。

### 6. 智能引用回复

- 回复可以引用触发她的那条消息（不引用 / 总是 / 智能三档，默认智能：回一串消息时才引用），
  她自己发的图片也算第一条。
- 群友引用一条消息再说话时，引用内容会进正文：还在聊天记录里就只点开头，
  已经不在留档里才写原文。

### 7. 多消息等待期与打断

- 连发两条只回一次：她还在调模型时，后面的消息并进同一次请求（默认 5 秒安静期，可配）。
- 生成期间、甚至动作做完但还没发出去时来新消息，这一轮作废重来；
  被作废那轮的消息还回队列、水位线不推进，新那轮仍然看得到。

### 8. 动作系统

- 提示词把「正在做 / 排队 / 已经做完」分开写，新安排可以用 `plan_mode` 排队、插队
  或顶掉没做的步骤。
- 「去别处做事」把别处才能做的动作连 id 和地点一起列出来，并写明"先 walk_to、
  紧接着写它照样能用"。
- 落点跟着"当时在哪个会话被安排"走；动作没做成时也会说一句并带上失败原因。

### 9. 提示词与上下文

- 上下文给足：聊天记录、她能说话的地方、此刻状态、可用动作 / 工具、她自己的账；
  聊天记录按是否回过分档给字（没回过的每条 500 字、已回过 / 别处 100 字、整段 4000 字预算），
  截断时标明「（这条还有 N 字没显示）」。
- 新增**水位线**：已经回过的不再重复回应，之后的原文才进「最近在聊什么」；
  判断用序号（同一秒里的消息不会被误判），水位线以下的也原样给她看、只标明"你已经回过话了"。
- 提示词按会话分：这条来自哪个会话、你现在在哪儿说话、最近那句是在哪儿说的都写清；
  聊天记录的时间戳带上日期，不再分不清凌晨和上午。

### 10. 会话组

- 几个群 / 私聊编成一组就是同一个她：位置、数值、心情、动作、计划、事件、日程、
  聊天上下文只有一份，额度也按整组算。
- 她自己挑说话的地方（群号 + 群名、QQ + 昵称，有备注用备注），一句话可以同时发给多个地方
  （群里应付一句、私聊吐槽一句）；记忆按会话各存一份，查的时候把同组的会话一起当条件。

### 11. 日程

- 日程可以选落点（会话 / 会话组），并支持只在那一天跑一次的**一次性日程**
  （跑完自动删除，可以写清"当初为什么排"）。
- 大模型也能自己排一次性日程；「提醒类」日程不再经过打杂模型，保留她的原话。

### 12. 情绪与表达

- 表达格从 3×3 扩到 **5×5（25 格）**，每格自己的心情词与说话约束；
  心情标签带**修饰**（困倦 / 想找人 / 闲得发慌…）与**来源**（`兴奋（因为：被哄了一下）`）。
- 情绪开始推"主动"：心情好时更想说话；日常的正面脉冲压小，不再连撩三句就"兴奋"。

### 13. 动作状态槽（跨插件状态同步）

- 动作可以把工具 / 指令的结果存成状态（例如别的插件的「今日穿搭」），
  之后每一轮提示词与状态页都带着；持续型动作一拿到结果就记。

### 14. 提示与文案

- 所有鼠标悬停提示重写：一句话说清这个配置干什么、取值与默认值，不再写沟通过程。

### 15. 合并转发摘要

- 合并转发的聊天记录交给低成本多模态模型压成摘要（默认 300 字，可改可关），
  按内容缓存，只在"这条要交给她处理"时生成。

### 16. 联网检索

- 一条完整流水线：她给意图 / 多条查询 → 辅助模型翻查询词 → 并发检索 → 整理成带编号的证据 →
  读正文 → 不够再补查 → 压成要点交给她；深度分**快查 / 标准 / 深挖**三档。
- 检索期间群里只出现一条「正在联网搜索」；慢动作（检索 / 生图 / 录视频）之前她已经说出口的话
  **当场发出去**，不再等整段流水线跑完。

### 17. 用户画像（通讯录）

- 新增「通讯录」页：**好友** 列 + 她能说话的地方；每个人一份画像——昵称 / QQ / 群名片、
  称呼（他让她怎么称呼自己、她怎么称呼他）、好感度（-100~100，带变化日志）、
  关系（含确立日期、历史关系、"他自称"）、关于他的事实（喜好 / 约定 / 习惯 / 近况…）、缩略版画像。
  可以手改、加事实、加/解除关系、调好感度、忘掉一个人；画像按**会话组**存（同一个她共用一份）。
- 提示词里给出「**你在跟谁说话**」：当前说话人全文（关系 + 日期 + 称呼 + 事实 + 现在能做什么 / 还不能做什么），
  以及群里最近说话的其他人各一行缩略版（默认最多 5 个）——她终于分得清人、也不会把画像当新信息反复问。
- 新增内置动作「**记住**」：她**当场**就能把值得记的事写进通讯录（事实 / 关系 / 好感），
  和睡眠整理共用同一套写入与校验——必须带"他的原话"、只认她真的见过的人、关系冲突照旧按关系表处理；
  「**回想**」也接上了它：翻到旧约定、旧印象已经变了时，可以接着用「记住」把新的情况改掉。
- **关系是"候选 + 代码校验"**：模型只提候选，槽位唯一性与冲突策略由代码决定（默认 `reject`：
  不改关系，把那句记成"他自称"，她能认也能不认）；一个人可以同时是主人 + 男友，
  但男友 / 主人 / 闺蜜这类唯一关系全组只有一个；解除后保留成"曾经"。
  垫底的默认关系（陌生人）在有了真关系之后不再并排展示。
- **同类关系（群友 / 朋友 / 闺蜜 / 男友 / 女友）在同一个人身上只留一条**：她判断成新的那条之后，
  旧的那条自动变成"曾经"（带起止日期）。升级和**降级**都算——她可以自己退回朋友、甚至翻脸；
  主人 / 家人这类身份关系不受影响，照旧能和亲密关系并存。
- **亲密度上限 = min(关系类型给的上限, 好感度达到的级别)**：群友怎么聊都上不到"亲亲"那一级，
  只有关系本身升级才放宽；每级分开配称呼、允许 / 禁止的动作与提示词文本，可勾"严格执行"
  把禁止的动作真的从选项里拿掉。
- 好感度自管（外部好感插件的标签照旧透传、不接管），数值只写进提示词由她自己判断做什么，
  不做硬门槛；负面关系（讨厌的人 / 敌人）与负好感也认。
- 称谓 / 事实都有防误判：称呼要"他明确说"才能覆盖已有的（黑名单直接拒），
  事实带原话证据、同类去重、正反冲突（喜欢辣 / 不喜欢辣）自动替换。
- **孤独拆开了**：群里热闹只说明"不闷"，不再算有人陪她——只有有人直接跟她说话才降孤独；
  新增"想念"（按人累积，跟群热闹无关），攒够了提示词里会写「你有点想他 / 她」，
  她可以主动私聊去找那个人。

### 18. 睡眠记忆整理

- 她**睡着时**（默认睡下 20 分钟）跑一次整理，对着人类的记忆机制做三件事：
  **消化**（原始聊天 → 要点 + 关于人的事实 + 关系候选 + 缩略版画像）、
  **重组**（同一件事合并、被确认过的旧记忆改写、回访时间按 1/3/7/30 天往后排）、
  **遗忘**（只"折叠"：正文换成一句要点，原话进 `context` 留着，**不删除**）。
- 整理节奏是"**一段睡眠最多两次**"：睡下 20 分钟第一次（把白天的经历消化掉），
  睡满 5 小时补一次（睡前最后聊的那几句这时才进去）；不是每 20 分钟轮一遍。
  小睡同样一段一次（轻整理）。三个时间点都可配（0 = 只整理一次）。
- 怕它整理得不好看：编辑器「通讯录」页有「**预览整理**」——照常组装输入、调模型、解析，
  但一个字都不写库，把提示词、模型原话、解析结果都摆出来给你看；每次整理的**模型原话**也会写进日志。
- 三道防编造：没带"他的原话"（evidence）的事实和关系一律不记；写给他的事实、关系、
  缩略版与好感变化只认材料里真的出现过的人（模型顺着昵称编出来的号码不进通讯录）；
  一次最多记 8 条事实 / 4 条关系。
- 整理要看到**上下文**：这段时间的原始群聊（带时间、谁说的、谁在场）+ 现有相关记忆 +
  她认识的人 + 挂着的约定与未完成的事；输出只要求"改动"（按记忆 id 合并 / 折叠），省一半 token。
- 单独的**睡眠整理模型**配置（留空跟随打杂模型）——一天只跑一两次，别用太小的模型。
  记忆整理与用户画像各有一个开关，默认都开；编辑器「通讯录」页有「现在整理一次」可以手动跑。
- 小睡只做**轻整理**（普通人小睡也会偶尔做梦）：要点化 + 刷新缩略版与近况 + 一条**梦**；
  不碰关系、事实与遗忘。梦是低权重的记忆，只进「想起」那一段，不进画像——第二天她可以顺口提一句。

### 19. 回想与记忆分层

- 记忆分两层：`raw`（原始片段，带当时的原话）→ `gist`（一句话要点，长期留着）；
  召回时给的是要点 + 「当时：…」的原话，她既记得住结论，也说得清细节。
- 记忆带**参与者**：一条记忆可以有多个人（谁在场、谁说的），召回可以按人过滤；
  「回想一下关于主人的事」会优先给跟他有关的那几条。
- 提示词里加了一条硬规矩：**关于过去的事先回想再答，别凭印象编**；想不起来就说想不起来。
- **回访队列**：值得记住的事会排"下次想起来"的时间，到点她会自己想起一件（每天最多 5 次、
  同一个人每天最多 2 次、同一件事 7 天内不重复提），并在提示词里写成「你忽然想起…」——
  想提就顺口提一句，也可以顺着这条主动去找那个人。
- 「召回 = 强化」：被想起来的记忆权重会涨一点（提取练习），不再只被降权。

### 20. 用户画像的设置面板

- 全局设置新增「**用户画像**」小节（在「记忆与上下文」标签里）：用户画像 / 睡眠整理 / 小睡轻整理三个开关、
  睡下多久开始整理、睡满多久补一次、提示词里最多带几个其他人、称呼黑名单，
  以及**关系表**与**亲密度分级表**（JSON 框，失焦即生效，再点保存）。
- 分级表的每一级都能改：好感区间、她怎么称呼他、允许 / 禁止哪些动作、是否"严格执行"、
  每天最多主动找他几次，以及**这一级写给模型的提示词文本**。

### 21. 默认世界重做

- 从「1 个区域 6 个房间」扩到「**5 个区域 21 个地点**」：家中（卧室 / 书房 / 窗边 / 吧台 /
  厨房 / 客厅 / 浴室）、商业街（街口 / 商场 / 小吃街）、学校（校门口 / 教室 / 图书馆 / 操场 / 天台）、
  公园（大门 / 长椅 / 湖边）、海边（步道 / 沙滩 / 礁石）；「大厅」改名**客厅**（id 不变，老配置照旧能用）。
- 区域之间走**跨区门户**（客厅↔街口、客厅↔公园大门、街口↔校门口、街口↔公园大门、公园大门↔海滨步道），
  从卧室到海边要 8 分钟、到天台 11 分钟——出门是有代价的。
- 动作从 31 个加到 **45 个**，新增的都是生活类：洗澡 / 泡澡 / 照镜子、追剧 / 瘫在沙发上、
  逛店 / 吃点小吃、旁听一节课 / 跑两圈、散步 / 喂猫鸽子、吹海风 / 踩水 / 捡贝壳（默认全开，时长由她定）。

### 22. 她是谁（插件自己的人设）

- 以前插件是"问 AstrBot：这个会话用哪份人格"，而那份人格**按会话 / 配置文件解析**——
  换会话组、换代表会话之后她就可能变成另一个人，甚至退回默认助理人格（连带"做完一件事想说一句"也会变成拒答或干脆不出声）。
- 「全局设置 → 基础 → 她是谁（人设）」新增角色卡：**跟随 AstrBot / 用插件这一份 / 两份接起来**三档，
  插件这份**所有会话与会话组共用**、写在世界配置里，**跟着预设一起带走**；留空时自动回落到 AstrBot 那份。
- 对话框里加了「从 AstrBot 导入当前人设」，一键把手上那份抄进配置从此固定下来。

### 23. 预设改成"分块应用"

- 以前应用预设是**整份替换**（地图 + 动作 + 世界设置 + 会话白名单 + 会话组一起换），
  切过去的瞬间会话和会话组就被预设里那份顶掉了，看着像"会话被清空"。
  现在是分块：**地图 / 动作 / 世界设置 / 人设 / 日程 / 会话**，勾中哪几块才换哪几块，**会话默认不勾**。
- 「清空所有会话状态」**默认不勾**：切预设保留原会话的上下文（位置、数值、计划、群聊留档）。
  不清状态时会**自动修状态**：站在新地图里不存在的地点 → 落到默认地点；计划 / 当前动作引用了
  不存在的动作或地点 → 丢掉并记一条日志。
- 修掉一类"会话和会话组一起消失"的半坏状态：会话白名单现在**按校验后的结果落盘**
  （会话组里引用已删除的会话会被当场清掉并给出提示），从白名单里删会话时也会顺手把它从会话组里摘掉；
  存预设时同样会过一遍校验并把提示返回给你。

### 24. 计划里的落点与"落地再问一次"

- 计划与回复的提示词里把 `send_to` 写成**硬要求**：凡是别人看得见的动作（说话 / 分享 / 发图）
  都必须写清说给哪个会话听；"我一会儿去群里说他"这类承诺也必须排进计划并带 `send_to`——只答应不动等于没做。
  没写时仍然按"就在他现在说话的地方答"兜底。
- 「走到新地方就地问一次大模型」加了闸门：**移动后本来就有安排**（同一串动作的下一步、或计划里排好的下一步）
  时不再多问一次；只有"只移动、没说到了做什么"才照旧问。日志里会写「落地后已经有『…』，不再额外决策」。

### 25. 好感度的日常：混脸熟 / 她自己的判断 / 慢慢回落

- 新增「**混脸熟**」：他露个面就加一点好感（不用 @ 她），同一人 10 分钟只算一次、每人每天封顶 +2；
- 回复 JSON 新增 `affinity_delta`（她对当前说话人的好感变化，跟"心情的 valence_delta"分开）：
  每轮最多 ±3，每人每天最多 +10 / -10——**私聊连着聊、被反复 @ 也涨不满**；提示词里写死了尺度，
  普通闲聊写 0，不许当成"聊得多就涨得快"；
- 新增「**慢慢回落**」：每天朝 0 淡 0.2（长期不理就慢慢忘），每个会话组一天只结算一次；
- 四条来源（混脸熟 / 她自己判断 / 当场记住与睡眠整理 / 慢慢回落）都会写进好感日志并标明来源，
  通讯录详情页显示最近 8 次。

### 26. 通讯录展示与缩略版画像

- 详情页新增「**概况**」一行：认识几天、聊过几句、昵称、各群名片、**关系上限**（说明为什么"挂着男友却还是客气"）。
- 防越用越长：历史关系默认折起来，事实默认只显示置顶 + 最近 8 条（其余点「还有 N 条」展开），
  好感日志只留最近 8 次并标出来源（混脸熟 / 她自己判断 / 慢慢回落 / 睡眠整理 / 当场记住）。
- 「缩略版画像」明确成**画像速写**：只写这个人的稳定特征（是谁、怎么说话、喜欢什么、什么关系），
  **不写他最近遇到的事**（例如"抽卡一发出了角色"）。整理提示词里加了这条硬规矩，
  近况请放进「事实 → 近况」或记忆。

### 27. 想念：不喜欢的不惦记、主动找人额度、软推

- **不喜欢的不惦记**：挂过「讨厌的人 / 敌人」或者好感是负的人，想念直接清零、不再累积。
- **「每天最多主动找他几次」接上代码**：分级表里那一档真的生效了——她自己主动对某人做事
  （抱抱、戳一戳这类）要花这一级的额度（陌生人 / 客气 0、熟人 1、朋友 2、亲近 3、特别的人 4），
  用完就跳过并写日志；**用户自己排的日程不受限**。
- **软推**（`miss_push_enabled`，默认开）：想念超过 0.85 时她会主动去找他一次，
  **在哪说由她自己决定**——想私密、想撒娇就发私聊，想让别人看到关系好就发群里；
  一天最多软推 2 次（`miss_push_daily_max`），推完那个人的想念清零。

### 28. 思维链不外泄 / @ 别人标清楚 / 想念分"见过 · 聊过"

- **思维链不会被当台词发出去**：她自己开口说话的那一轮里，模型要是只给了推理、
  没给要说的话，就按"保持安静"处理；以前这种情况会把整段 JSON（连 `reasoning` 一起）
  原样发到群里。
- **聊天记录里的 @ 标清楚**：@ 的是她写成「你（昵称(id)）」；@ 的是别人会补一句
  "（其中 小明(42) 是别人，不是在 @ 你）"，她不会再以为是在叫自己。
- **想念把"见过"和"聊过"分开**：他只在群里露个面（哪怕一直在刷屏）不算陪过她。
  想念看的是"上次跟他说话是 X 前"，另外会补一句"他 10 分钟前在群里露过面"，
  让她知道人还在、只是没来找她。
- **想念不再是固定节拍**：他跟她说完话（或者她刚主动找过他）之后，想念先归零，
  再在 `miss_cooldown_min_minutes`（默认 45）到 `miss_cooldown_max_minutes`（默认 240）
  之间**随机**等一段才重新开始涨——不会规律地隔固定时长去打扰同一个人。

### 29. 好奇心会涨也会被满足：不再一醒来就疯狂上网

- **睡一觉会放下**：睡觉 / 小睡期间好奇心按 `sleep_curiosity_decay_per_min`（默认 0.0012）回落，
  最多压到 `sleep_curiosity_floor`（默认 0.3）。以前睡眠是把数值冻结的——她会带着白天攒的
  满格好奇心入睡，醒来所有门禁一放开就冲去查东西。
- **查完就满足**：检索型动作**真拿到结果**之后，好奇心按动作里的
  `search_satisfy_curiosity`（默认 0.3）降一次。原来那点 `curiosity: -0.06` 只够抵消一小时的自然增长
  （好奇心是 1.44/天往上涨的），压不到 0.7 这条线以下，于是冷却一到又去查同一件事。没查到东西不算满足。
- **越接近满值涨得越慢**：过了 0.7 之后增长速度按剩余空间递减，到 1.0 时归零，
  好奇心是渐近贴近满值而不是一天顶死在那里。
- 顺带说清一件事：`state_dynamics` 里"搜索中每分钟 −0.002"那一条对**瞬时**的检索动作从来不生效
  （瞬时动作不会进入 `searching` 状态），所以这件事交给上面的「查完就满足」——持续型的检索动作两边都会吃到。

### 30. 想念跟孤独挂钩 / 同一条短消息不再被记成两遍

- **越孤独越想他**：想念的涨幅多了孤独这一层——`×（1 + miss_loneliness_weight × 孤独感）`，
  默认权重 0.8 就是"孤独满时快 1.8 倍"。刚聊得热乎时按原速，没人陪她时更容易想起某个具体的人。
  想念这几个参数（涨幅 / 孤独加成 / 阈值 / 冷却区间 / 软推开关）一并搬进了
  「全局设置 → 用户画像 → 想念」。
- **同一句短消息不再记成两遍**：一条消息会经过「旁观监听」和「LLM 请求」两个钩子，
  其中一个会带上「［这条消息 @ 了：…］」这种注释。原来的去重要求"内容基本一样"且最少 4 个字，
  于是「亲亲」这种两个字的短消息会被存成两行，她就以为对方连着说了两次。
  现在比较前会先把注释尾巴切掉（这类重复可以放宽到 10 分钟内的排队延迟），
  提示词渲染那一层也按同一套规则去重——老存档里已经存进去的重复行同样只显示一行。
- **跨会话的同一句话说明白**：「你在别处同时听到的」那段补了一句——同一句话在两处出现，
  是他在**另一处**说过的话，不是在这里又说了一遍。

### 31. 调试回显跟着"这件事发生在哪个会话"走

- **修**：在私聊里让她做个指令型动作（例如「/看看腿」），她的回复确实发在私聊，
  但 `🧩 执行指令` 那一行却跑到了群里。原因是这几条回显用的是一个**复制出来的 outcome**，
  复制时把「发生在哪个会话」弄丢了，于是回显掉回她存档的那个会话（通常是群）。
  现在复制时会把发生地带过去，`🧩 / 📤 / 🗓️ / 💭 / 📖 / 🪪（状态槽）` 这些走同一条路的回显
  全都跟着实际会话走。
- 同一类漏点一并补齐：**日程**（落点勾了私聊）、**手动跑日程**、**投递事件 / 推进线索**、
  **刷新天气**、**触发决策** 这几条入口都补上了「发生在哪儿」——
  这些地方以前也会把回显发进群。

### 32. 私聊戳一戳 / 聊天记录按行算 / 分会话摘要 / 互动动作

- **私聊戳一戳走对路了**：`poke` 消息段是群聊专用的，私聊里发出去客户端只会显示成一个
  认不出的占位（红叉破图）；而那条路线只要"没抛异常"就当成成功，`friend_poke` 根本没机会跑。
  现在**私聊不走消息段**，直接 `friend_poke`（退 `send_poke`），群聊保持原样；
  日志里会写明这次走的是哪条路，两条都不通才退化成一句动作文案。
- **聊天记录按"合并后的行"算**：同一个人的连着几句话并成一行（认人用 QQ 号，昵称 / 群名片变了
  也算同一个人；「你在别处同时听到的」那段以前完全不合并，现在一起并）。
  进提示词的上限从"12 条原始消息"改成 **20 行**（`decider.chat_max_messages`，
  编辑器里挪到了「上下文 → 带进提示词多少行聊天记录」），老配置里还是旧默认值的自动升级；
  一个人连发十条只占一行额度。整段聊天记录的字数预算从 4000 提到 8000。
- **「更早聊过的」分会话总结**：一个会话组里的群和私聊共用一份留档，以前压出来的摘要是**一段混着的**；
  现在按会话各压各的（`chat_summaries`），提示词里分成
  「更早聊过的（这里）」「更早聊过的（私聊 …）」；「清空上下文」也只清当前会话。
  老存档里那份全局摘要会挂到存档会话名下，不会丢。
- **30 个互动动作**：点头 / 摇头 / 鼓掌 / 歪头 / 眨眼 / 击掌 / 拍肩 / 递纸巾 / 分你一半 /
  揉乱头发 / 扯衣角 / 撞肩膀 / 捏鼻子 / 冰手偷袭 / 咬肩膀 / 咬手腕 / 牵手 / 靠肩膀 / 蹭蹭 /
  捏脸 / 闭上眼 / 亲额头 / 擦眼泪 / 揉肩 / 披外套 / 十指相扣 / 钻怀里 / 投喂 / 接吻 / 耳边说——
  按亲密度铺开，效果（孤独回落 / 心潮）也是按档递增的，都不越界。
- **说明能简写**：动作新增 `desc_mode`（完整 / 只写名字）。「看一眼名字就知道干嘛」的动作
  （点头、抱抱、亲亲…）只写 `- nod（点头）`，几十个这样的动作不再各带一句废话；
  工具型、时长由你定、只有这个地点才能做这些标记照旧保留。
- **提示词补齐了六件事**：日程到点会自己跑（带前因再问一次、只落在能说话的地方）；
  清单里没有的动作就是现在做不了（别答应做不到的事）；亲昵上限取「关系类型允许的」和
  「好感够不够」里更严的那个 + 动作按距离分档（打招呼 → 打闹 → 亲昵 → 最亲密）；
  会话组里"位置/心情/日程/记忆/关系只有一份"、一件事可以一次给两处各写一句；
  别的插件给的状态是"你调动作后系统替你记下的，下一轮还在"；睡着时系统会替她整理记忆与画像。

### 33. 聊天记录注入对账：一个口径、一个额度、一份背景

把"聊天记录怎么进提示词"整条链路对了一遍，修掉五处口径不一致：

- **额度按会话各算**：以前是在所有会话的留档上一起取"最近 N 行"，于是私聊聊得多的时候
  群里刚说的话会被挤出去（实测：群里 3 条没回的 + 私聊 20 组 → 群里那 3 条一条都进不去）。
  现在本会话取 `chat_lines` 行、别处取 `chat_elsewhere_lines` 行，互不挤占。
- **单位统一成"合并后的行"**：同一个配置项以前在"进提示词的视图"里按行、在
  "插话判定 / 工具选型 / 编辑器计数"用的那套视图里按**原始条数**。现在只有一个实现
  （`take_last_chat_groups`），两边一致：一个人连发十二条只占一行。
- **三个行数都成了配置**：`chat_lines`（每个会话没回过的，默认 20）、
  `chat_answered_lines`（已回过的那批，默认 30）、`chat_elsewhere_lines`（别处，默认 12），
  都在「上下文」里；老配置里的 `decider.chat_max_messages` 自动迁到 `context.chat_lines`。
- **「刚才在聊什么」按会话存、每次都给她看**：以前 `chat_note` / `chat_preview` 是全局一份
  （群里写一句、私聊写一句互相覆盖），而且只在"没有已回过原文"时才显示——提示词里明明
  告诉她"下一轮你会看到它"，实际几乎看不到。现在按会话存、放在「更早的聊天」里每次都带，
  并加了 `chat_note_max_minutes`（默认 30 分钟，超时不再当"刚才"用）。
- **留档按会话各自保留**：以前整个会话组共用一份留档，一个热闹的群能把私聊的记录挤光；
  现在每个会话各留 `chat_history_max` 条。顺带修了个细节：留档条目现在**在记下来的同时**
  就带上来源会话（以前是记完再补，裁剪时会把私聊那条算到群头上）。
- **编辑器那两个数改成实话**：「未回应 / 已回应」现在只算**当前会话**、按水位线分、按行数算
  （以前"已回应"是用留档总数减出来的，把别处会话和时间窗之外的都算进去了）；
  「群聊上下文」面板改成按会话列出各自的摘要。

### 34. 修：她"只在私聊口头答应"、不去别处说

- **最末尾那句提醒把跨会话能力否掉了**：多会话时提示词结尾写着
  「4. **只能在你现在说话的地方说话**…」——本意是"名单外的会话去不了就别答应"，
  但读起来就是"只能在这儿说"，于是她在私聊里答应"我去群里说晚安"之后真的不动。
  现在多会话时改成：「你能说话的地方」名单里的地方你都能去（换地方说就写 `send_to`）；
  名单外的才去不了。顺带在最后确认里补了一条「答应了要去别处说，就必须把那条 say
  写进 actions 并写上 send_to」。
- **"现写一句"这条路以前不带「你能说话的地方」**：`say` 没给文案 / 分享 / 单轮动作
  （听你说、打气…）是由模型现写台词的，那条提示词以前没带会话目录、也没告诉它"现在在哪儿"，
  所以她既不知道能去别的会话说，还把别处的话当成"这里"。现在这条路一并带上
  会话目录、当前会话与会话标签。

### 35. 修：指令型动作报 `'str' object has no attribute 'chain'`

- **原因**：借别人的指令跑时，我们自己去读它的参数注解。插件的 `main.py` 只要写了
  `from __future__ import annotations`（很常见），注解就是**字符串**，AstrBot 自己是用
  `inspect.signature(..., eval_str=True)` 还原成真类型的；我们没做这一步，于是
  `validate_and_convert_params` 把字符串注解当成"默认值"原样透传——需要对象参数的指令
  （例如参数是 `MessageChain`）收到的是一个 str，一访问 `chain.chain` 就炸。
  同一个坑还会让 `GreedyStr`（吃掉剩余文本的那种参数）失效。
- **修法**：参数类型优先用 AstrBot 自己解析好的 `CommandFilter.handler_params`，
  兜底路径也改成 `eval_str=True`。
- **可诊断性**：指令跑挂时，日志与返回值里现在会带上"最后落在哪个文件哪一行"，
  例如 `AttributeError: ...（main.py:123 handler）`——报错来自别的插件时一眼能看出是谁的锅。
- 真机复现过：装一个"参数是对象"的测试指令，修复前日志正好是
  `跳过：查天气的指令「/天气 武汉」没跑成：AttributeError: 'str' object has no attribute 'chain'`，
  修复后同一条指令正常返回天气内容。

### 36. 「最近发生的事」不再列"说话 / 想事情"

- 那段本来该写"她**真的做了什么**"（走动、做饭、伸懒腰、被人打断…），
  以前把她自己开口说一句、心里想一下也当成"做过的事"列进去，
  既和聊天记录、和「你最近说过的话」重复，又把真正发生的事从这 5 个位置里挤出去。
- 现在 `say` / `think` / `share` 三类不进这一段；亲昵动作、伸懒腰这类"确实做了点什么"的照旧列。
  编辑器状态页与日志里的原始记录**照旧完整**（她做过什么都能查到），只是提示词里不再列。
- 顺带把"发言等待回应"这类碎片记录也挡在外面：它们以前会渲染成一行原始数据
  （`bot_spoke: {'world_time': …}`）塞给模型，占位置又看不出所以然。渲染不出人话的记录一律跳过。

### 37. 情绪量程：聊天不再能把效价顶满

- 以前一次对话最多能把效价推动 ±0.2，而她生活里真经历一件事最多才 ±0.1——
  **最高频的事反而是最有分量的**。结果是随便撩两句就顶到满值，之后一直卡在
  "欢呼雀跃"那一格（表达方式也就永远同一句），"100 分"变得毫无意义。
- 现在聊天这条路：单轮最多推动 ±0.05，一天正向累计最多 0.15（可配）。
  日常陪伴改的是**好感度**（那才是长期关系），不是心情的量程。
- 提示词里的 `valence_delta` 从"给个范围"改成了**带锚点的刻度**：0 = 没什么感觉（日常聊天基本都在这）、
  ±0.2 = 几小时都还想着、±0.5 = 这一天的基调被改写、±1 = 记一辈子。
  示例 JSON 里的示例值也从 -0.2 改成 0——以前那是在教模型"每轮都要写一个数"。
- 「连着被哄会麻木」：被叫 / 被夸 / 被哄这三类高频脉冲第二次起幅度递减
  （1.0 → 0.6 → 0.35 → 0.2 → 0.12 → 0.08），隔 20 分钟没有同类好事才重新按第一次算。
- 边际递减的地板从 25% 压到 10%：越接近满值越推不动。**满值只留给真的极端时刻**。
- 实测（连续快速聊天、模型每轮都写最大值）：效价从"第 4 轮就 1.000"变成"顶在 0.73 左右"，
  心潮从"第 11 轮 1.000"变成"稳定在 0.59 附近"——正好落在"有点起伏"而不是"激动得不行"。
- 两道额度是**所有聊天路径共用**的：关键词兜底的「被夸 / 被哄」也从同一份额度里扣，
  不然总有一条路能绕过去。负面不受额度限制。真机复核：额度用完后，继续聊 6 轮效价纹丝不动。
- 状态页「互动与运行」里新增一行「聊天的情绪额度」，能看到今天已经推了多少、还剩多少。

### 38. 改动历史：每次改配置都留一版，随时翻回去

- 以前只在「应用预设」时备份，手滑改坏了人设 / 地图就只能靠记忆修。
  现在**每次写配置之前**都会先把那一版存下来：手动保存、应用预设、恢复默认、
  日程被自动回收…都留档，并且写明来源（`手动保存` / `应用预设` / `恢复历史` / …）
  和"相对上一版改了哪几块"（地图 / 动作 / 世界设置 / 人设 / 日程 / 会话）。
- 编辑器「预设」页多了个「改动历史」按钮：左边时间线（时间 + "x 分钟前" + 来源 + 改动摘要），
  右边看它跟**现在**的差别，可以**只挑某几块恢复**（例如只把人设恢复回去，地图不动）。
  恢复前的那一版同样会留档，所以"恢复"本身也能再恢复回来。
- 只留最近 50 条，**内容没变的不重复占位**（连点保存不会把名额挤满）。
  早期版本留下的 `before-apply-*.json` 一并列出来（标成"旧版备份"），但**不参与滚动删除**。
- 顺手修掉一个老 bug：旧备份文件名精确到秒，同一秒连点两次会互相覆盖。
  现在文件名带毫秒与内容指纹。

### 39. 她终于知道"上次跟你说话是多久前"

- 想念那条线一直有这对数（他多久没找过她），但**只在她主动找你时才算**；
  你来找她的时候，她反而不知道你们隔了多久，"你昨天说的那个"就永远落不了地。
- 现在「你在跟谁说话」里多一行：`他上次跟你说话是 2 小时前；他 3 分钟前在群里露过面`。
  两个时间分开说——他在群里刷屏但没找她，一眼看得出来。

### 40. 「她是谁」这一页改名「她 / 他 / ta」，并收拢成一个人

- 标题不再写死"她是谁"，直接跟**性别设置**走（她 / 他 / ta）；预设里那个分块的叫法也跟着变。
- 构成"这个人"的设置都收到这一节下面：**性别**、**Bot 名称**、**人设来源**、**角色卡**、
  **声音样例**、**简易人设（给打杂模型）**——以前它们散在「基础」和「记忆与上下文」两页。
- 分区归口从"按标题字符串"改成**稳定 id + 显示标题**两套字段：标题会随性别变，不能拿它当身份。

### 41. 声音样例：让她照着"她自己说过的话"来说

- 角色卡只有描述，模型是在"照规范表演"；**模仿样例的效力远大于服从描述**。
  现在可以按场景让内容生成模型出候选（被撩 / 被怼 / 被冷落 / 深夜 / 群里被点名 /
  越界请求 / 她自己正在忙…），每个场景给三条**不同走法**（反问 / 拆台 / 只说半句 / 直接拒绝…），
  你挑中的才进配置——生成物永远只是草稿。
- 注入规则：接在**第 1 层人设之后**，每轮最多 3 条、先按这一轮的场景对（被哄就抽"被撩"那组），
  **连着两轮不抽同一组**（免得她变成复读机）；一条样例都没有时，这一段**整段不出现**。
- 文案里明写「这是口吻样本，不是这一轮要说的台词」——不写这句，模型会整句照抄。
- 样例库最多 12 条（可配），跟着预设走；生成器用的是「内容生成模型」，值得配好一点的。
- 顺带把两处"预览和实跑不一致"补齐：**声音样例现在在预览里也看得到**
  （之前自主提示词/注入内容的预览都不带它，「你在跟谁说话」那段也一直没进预览）。

### 42. 优化人设：先体检，再让你逐条挑

- 直接让模型"帮我优化人设"会干两件不想看到的事：**把它改长**（人设是每轮都进提示词的第 1 层，
  长一截就挤掉后面的规则）、**把它改通用**（往"温柔可爱善解人意"的模板收，个性被洗掉）。
  所以顺序是：**先体检，再按问题改**。
- 体检按七条查：重复插件已经在做的 / 缺可演维度 / 形容词没落地 / 自相矛盾 / 篇幅 /
  不该出现的（元信息、助手腔、和机制冲突的设定）/ **怪癖要保护**。
- 产物是**差别**不是新稿：每条 `改：原文 → 改后`、`加（口头习惯）：…`，你在界面上勾哪条就写哪条；
  **找不到原文的条目直接跳过并报出来**（你手改过人设之后不会硬写）。
- 硬约束：身份、名字、性别、称呼、关系、禁区一个字都不许动；改完落在原文字数的 80%~150% 之间。
- 写进角色卡之前自动留一份历史，随时能翻回来。

### 43. 测评剧本：一份考卷，测不同模型演得像不像

- 按角色卡写 20 轮：场景 / 用户原话 / 这一轮看什么 / 禁忌。**不写角色会怎么回答**——那是要考的东西。
- 同一份拿去跑不同模型，你盲选哪版更像她。
- 这份东西**绝不进她的提示词**：进了就是背题，测不出模型能力。
- **出完题先给你过目**：弹窗里逐条列出"要问什么 / 看什么 / 禁忌"，你确认了才开跑。
- 点「开始跑」就**并发**把每一轮喂给"带着完整提示词的她"（人设 + 声音样例 + 状态 + 画像 +
  聊天记录），拿她的**真实回复**摆出来给你看，每轮还能展开看她当时的判断。
- 关键：**这一路不写任何状态**——水位线、记忆、心情、动作都不动，所以能反复跑、跑十遍也不会
  污染她的世界。想比模型就把"模型 id"填成另一个 Provider 再跑一遍同一份考卷。

### 44. 还没聊完的事：她会接着问

- 聊天记录里只有「刚才在聊什么」（30 分钟就过期），所以话题一断她就再也不提了。
  她**不会问"你昨天说的那个后来怎么样了"**——这正是"每轮都在应答"和"在跟我过日子"的分界。
- 现在主模型可以写一个可选字段 `open_topic`（他说明天去体检、他在纠结换工作），
  代码记成一份账本：**到点、且这个人再出现时**才提醒她可以接一句；不到点不提（像查户口）。
- 退避与上限：问过一次还没结果 → 延后重来，**最多两次**就先放下；挂了一周自动归档；
  同一个人身上同时最多两件；一份会话里最多四条。
- 只记**别人的事**：她自己的安排有事件与日程管，重复记账会打架。

### 45. 采样参数可以接管了（可选）

- AstrBot 插件设置里新增一组开关：**接管采样参数**（默认关，关着就是原来的行为）。
  打开后本插件发起的调用会带上温度 / top_p / frequency_penalty / presence_penalty。
  多轮聊天复读、腔调固定，一半是采样参数的事。
- 稳妥起见做了兜底：Provider 不认这些参数时**自动退回只用温度**，不让主回复跟着挂掉；
  日志里会写一句，告诉你"要调就去 Panel 的 Provider 里调"。

### 46. 界面：两处"看不懂"的地方改成能看的

- **优化人设**原来是挤成一行的长文本（"改：原文 → 改后"一句到底），根本看不出改了什么。
  现在是自己的弹窗：左边是体检结果（每条带「建议改 / 和插件机制冲突」标签、原文片段引用），
  右边一条一张卡：**原文划掉 → 改后**，新增的显示成「新增·口头习惯」。
  勾哪条才写哪条，底下一行实时显示"已选 n / m 条"。
- **关系表 / 亲密度分级**原来是两个 JSON 输入框（改个上限都得对着括号数数）。
  现在是一行行表单：
  - 关系表：名称 / 槽位 / 好感上限 / 别名 / 唯一 / 负面 / 初始，右边 ✕ 删除，底下「＋ 加一种关系」；
  - 亲密度分级：档位名、好感区间、称呼、每天主动次数、这一档的提示词、允许与禁止的动作（写 id，逗号分隔），
    整档用卡片包起来，同样可加可删。

### 47. 情绪判断不再靠关键词猜

- 「他是在夸她还是怼她」以前是**词表匹配**（`hug / positive / negative`），
  所以"你可真行啊"会被当成夸奖。现在由**主模型**在回复 JSON 里多写一个字段
  `tone`（`praise / hug / attack / normal`）——它本来就要读这一整句话，多输出一个词不花钱。
- 提示词里明确写了看真实意思：「你可真行啊」是 attack；熟人式的「大肥鱼」这种逗她也是 attack。
- 关键词表**保留为兜底**：模型漏字段、或这一轮压根没走到模型（睡着被挡下）时还用它，
  所以行为不会比现在更差。日志里新增 `tone` 字段，信号判错时一眼能看出来。
- 顺带：`tone` 判完还会给一次情绪脉冲（被夸 / 被哄 / 被怼），她"被哄得开心"不再取决于字面。

### 48. 测评加了两条：动作会不会用、口吻有没有判对

- 动作这条线以前**测不出来**：测评用的白名单比真机宽松，怎么胡写都不会被丢。
  现在测评用**真实白名单**（当前地点能做的动作）解析，写不出来的动作会被丢掉并记在结果里，
  结果里还会列出「这一轮她手边本来能用哪些动作」——一眼能看出她是不会用、还是没得用。
- 工具/动作的 `intent` 也一起记下来（她到底想让工具干什么）。

### 49. 追剧不再只会干吐槽：动作也能留状态槽了

- 追剧以前只能来一句"这剧情真离谱"——因为**"她在看什么"从来没被记下来过**，
  而且提示词里当年还写着"不要报剧名"。
- 现在：**非工具型动作也能写状态槽**（`state_slot`）。追剧 / 看书这类动作说出的内容
  （剧名、情节）会记进「在看的剧 / 在读的书」，之后每一轮提示词里都带着，
  不会每次都对同一个剧重新开始。
- 提示词也改了：要求**说清在看什么、看到哪、什么感受**，并且「上面已经有了就接着往下说」。
- 实测（真模型 + 她的角色卡）：追剧 →「补完了两集《迷宫饭》／法琳变成奇美拉莱欧斯第一反应居然还是能不能吃……
  ／制作组是这样的」；看书 →「摸鱼看了半小时《企鹅公路》／看到大姐姐随手把可乐罐变成企鹅了／难蚌」。

### 50. 「做完饭拍张照」现在真的能做

- 续说那一轮**本来就允许排动作**（只有"刚查完又查""链条太深"两处闸门），
  缺的只是没人告诉过她可以这么干。现在 `做饭` 的「完成后」提示词里写了：
  「想拍一张就给这顿饭拍张照——在 actions 里紧接着排一个拍照动作（selfie），拍完再说话」。
- 实测输出：`[{"type":"selfie"},{"type":"say",…}]`——先拍照，再说话，顺序正确（拍照是全地点可用的动作）。

### 51. 「想找谁」那个数值露出来了

- 以前想念值只活在代码和日志里：她到底惦记谁、离"会主动去找"还有多远、今天还剩几次额度，
  编辑器里看不到。
- 现在**控制台页**多一行「想找的人」：
  - 正在惦记的人 + 想念值 / 阈值（到阈值她就会自己去找他）；
  - **刚聊过、还在冷却里的人**：标出"还要多少分钟才会开始想他"——
    不然"她怎么不想我"完全看不出来（刚说完话就把想念清零是设计如此，不是 bug）；
  - 今天的主动找人额度用掉了几次。
- **通讯录**里每个人的详情也加了一行「想念」：这个人的数值 / 阈值，或者"刚聊过，X 分钟后才会开始想"。

### 52. 修：通讯录打开有"喜好 / 事实"的人就整块读不出来

- 报错是 `target.appendChild is not a function`，画像区整块空白。原因是这一行：
  `visibleFacts.forEach(factRow)`——`Array.prototype.forEach` 传给回调的是
  `(元素, 下标, 数组)`，而 `factRow` 的第二个参数是"往哪个容器里放"，于是 `target` 拿到 **数字 0**，
  一 `appendChild` 就炸。只有这个人有事实条目时才会走到这段，所以"有些人打得开、有些人打不开"。
- 改成 `forEach((item) => factRow(item))`，并加了一条**前端静态检查**：
  再出现 `.forEach(函数名)` 这种写法直接测试失败（这个坑很容易再踩一次）。

### 53. 改动历史：改成"改了哪几处"，不再是倒 JSON

- 以前是把两边的 JSON 逐行比，然后把"删掉的行"和"新增的行"各列一坨——
  光 `设置` 那一块就好几千行，根本看不出动的是哪一处；左侧列表文字长了还会顶出格子。
- 现在**按路径递归比**，一条一条列：

  ```
  设置：3 处改动
  persona.text        [改动]
    - 她很温柔。
    + 她嘴硬心软，被哄会别过脸。
  ```

  路径写成 `persona.text` / `profile.bonds[2].cap` 这样，一眼知道动的是哪一项；
  新增的标「新增」、删掉的标「删除」。
- 左侧列表也跟着修了：长文字换行、最多两行，不再顶出格子。

### 54. 「群里没人理 → 去私聊说」这条链路查清了，并加了一道约束

- **这条确实是模型自己判断的**，但不是凭空：链路是
  「她主动说话没人理 → `unanswered_count` 增加 → 触发 `ignored`（心情↓、孤独↑）→
  孤独越高想念涨得越快（`miss_loneliness_weight`）→ 想念到阈值 → **想念推** →
  系统让她自己写一份计划，并明说『在哪说由你自己决定：想私密就发私聊』→ **她自己选了私聊，内容也是她自己写的**」。
  另外想念值只要过 `miss_threshold`，在**任何一轮**的正常提示词里都会出现「有点想他」，
  她也可以随时自己写一条 `send_to=私聊` 的话——这也是模型判断。
- 会"把群里那句搬到私聊"，是因为她的上下文里就有刚说过的那句，而那句提示词**没禁止她重说一遍**。
  现在想念推的提示词里加了：
  「**换地方说 ≠ 把刚才那句话再说一遍**。如果你刚在群里说过一句、没人理，就别把它原样搬到私聊——
  要么接着往下说（"刚才那个…"），要么说点别的（你正在做的事、你自己的事）。」
- 代码里**没有任何"把群消息转发到私聊"的逻辑**（跨会话发言只有一个来源：模型自己在 `send_to` 里写）。

### 55. 事件改成"全部临场生成"，内置事件池整个删掉

- **删掉了 38 条内置事件池**，连配置项和编辑器那一页一起删了。池子是死数据：写的时候不知道她
  此刻在哪、在做什么、心情如何，落到具体情境里就总会有一股"编的"味道；而且同一条被抽中两次，
  群友一眼就认出来。
- 现在**每一档都由生成模型按当前场景现编**——包括以前完全走池子、一次模型都不调的微事件。
  生成失败（没配模型 / 模型没给出可用的包）就当这一轮**没出事**，不会塞一条假事件顶上。
- 题材仍然由**代码按权重掷**再交给模型（模型自己分配比例时只会挑偏好的那类写，
  结果永远是"温馨小事"）。地点、当前动作、红线、她最近的记忆都会一起进生成提示词。

### 56. 事件不再"尬"：五个配套的修法

- **大事件最少演两幕**（`big_min_steps`）：模型忘了留伏笔就由代码补一步。以前大事件经常一步收尾，
  比小事件还潦草（"有人找我麻烦"下一句就是"我自己解决了"）。
- **题材冷却**（`genre_cooldown_minutes`）：同一个题材用完之后一段时间不再抽中，最近用过的还要
  多排几件。权重 40% 的「日常小事」光靠"排除最近 N 条"压不住，隔一件就又回来了。
- **「没成」不等于「受伤」**：结算提示词里给了一份失败写法菜单（搞砸 / 误会 / 丢东西 / 白忙 /
  被怼 / 网卡 / 东西坏了 / 被拒绝 / 迟到 / 记错了），并明确要求"别一连几次都写成磕了碰了流血了"。
  实测对比很清楚：老数据里连着三步都是"剪破尾鳍 / 渗着血"。
- **失败也有收获**：失败时结算必须写出她**知道了什么**，代码侧保证至少给一点能力值成长；
  判定档位的负向情绪幅度也收窄了（连着两次没成不该把她一路推到谷底）。
- **结果进聊天留档**：事件收尾那一幕的结果会作为一条**「她自己身上发生的事」**写进聊天记录
  （标着 `internal`，不算"还没回的消息"）。以前结果只活在提示词的另一段里，
  所以她日后提起"我前两天把锅盖拧死了"这种话永远落不了地。`event_digest` 保留条数 6 → 12。

### 57. 分享策略：平常静默推演，只在节点上说

- 以前**醒着就必发**：每一幕都往群里丢一句，一个人没头没尾地尬演就是这么来的。
- 新增三档策略（微 / 小 / 大各一份，`silent` / `nodes` / `always`，默认 `silent` / `nodes` / `always`）：
  - `silent`：只进状态与记忆，一声不吭（微事件默认这一档）；
  - `nodes`：只在**开场和收尾**那两幕说，中间静默推演（小事件默认这一档）；
  - `always`：每一幕都可以说（大事件本来就是值得讲的）。
- 事件仍然照常影响能力值、情绪与记忆——**不说不等于没发生**。写进留档的那条记录，
  就是她日后的谈资。
- 默认红线补了四条：不写"她意识到自己是 AI"这类自我指涉、不写真实群友之间的吵架、
  不写流血受伤生病、不写灵异恐怖。

### 58. 事件模型单独一个槽位（`event_provider_id`）

- 一件事件读起来尬不尬，几乎全看结算那句"最后怎么样了"。它以前混在打杂模型里——
  那个模型还兼着补工具参数、压上下文这些活，配置上只能一起换。
- 现在拆出独立的「事件模型」（留空跟随打杂模型）：想让它更强就换它，不用连带换掉别的打杂活。
  它输出的东西很短（一句结果 + 几个数），开好一点的模型代价可控。
- 顺带把「内容生成模型」的说明改对了：它不只管编辑器里生成动作 / 地点，事件包也归它编。

### 59. 「没人理」时的三处改法

- **她求助没人接时那句自我圆场，不再写死**。原来是代码里三句固定台词
  （「算了，本小姐自己来。」…）——不管用户的人设是什么，她都会突然冒出一句"本小姐"，
  一句就把人设打破。现在**由模型按人设现写**；写不出来就**不说话**（静默收尾比说错话强）。
  新增开关「她求助没人接时，补一句自我圆场」（默认开）。
- **LLM 预算用完后不再退到内置短句池**。以前会用一句写死的通用台词（「……有人在吗？」）
  顶上，跟任何人设都不搭。现在**保持安静**——说错话比不说伤害大得多。
  同时把每小时预算放宽（被动回复 15→40、自主发言 6→20、自主行为 2→6、分享 1→4、
  计划 4→10、工具参数 30→60）。
- **自主开口的提示词里补上"刚才没人接"这个状态**：以前这句话只写在系统提示词里、
  位置靠后，模型经常当没看见。现在挪到用户提示词里紧跟"接下来做什么"，并写明默认倾向——
  **没人接的时候，下一轮大概率就别追着说了**；同时和被动回复共用同一套措辞分寸
  （别吆喝、别招揽、别讨好、想不出就保持安静）。

### 60. 声音样例改成"候选池 + 已采用"两栏

- 以前「生成候选」必须**当场挑完**，不挑就丢；攒不下来、也没法回头再选。
- 现在左边是**候选池**：生成出来的、从聊天里挑出来的都先攒在这儿（最多 80 条），
  可勾选、可删除；右边是**已采用**——只有右边才进提示词。
- 新增「**从近期聊天挑**」：翻她近期说过、而且**后面有人接话**的句子，连当时对方说的那句
  一起列出来（没人接的那几句不进候选——学会了就是教她"没人理也要继续说"）。
  每条会自动打个场景标签（被哄 / 被怼 / 安慰…），进提示词时仍然按场景抽。

### 61. 声音样例的"场景"接线修好了

- 「每轮抽 2~3 条**相关的**样例」原来是**没生效的**：`signal` 取的是一个从来没被赋值过的字段，
  而且词表还对不上（上一轮判口吻产出的是 `praise / attack`，这里要的是 `positive / negative`），
  结果是每轮都在纯轮换。
- 现在改用**上一轮主模型判的口吻**（它认得反话）映射到 `hug / negative / positive`，没有才退回
  关键词表。被夸的时候抽"哄人"那组、被怼的时候抽"被怼"那组，才真的成立。
- 顺手清掉了 `handle_incoming` 里那段基于同一个字段的死代码——它会让同一句"亲亲"被算两次情绪脉冲。
- **候选池不再占页面**：设置页只留「已采用」+ 三个按钮，候选挪进弹窗（勾选采用、✕ 删除、可一键清空）；
  **已采用的每条都能改**（文案 / 场景 / 动作说明），不用删了重加。

### 62. 关系不再只看好感：绑了男友就能抱抱

- 以前生效档位是 **min(好感档位, 关系上限)**，于是"绑了男友但好感 20"会落到「熟人」，
  提示词里同时写着"他是你男友"和"你们还不熟，别贴贴"——**自相矛盾**，抱抱亲亲也都被禁掉。
- 关系表新增「**最低档**」（floor）：生效档位 = 好感给的档位，先被最低档抬起、再被最高档压下。
  默认数据里男友/女友最低到「亲近」，所以**绑上就能抱抱**，好感再往上才走到"特别的人"；
  而"普通关系不能亲亲"这条没动——群友封在「熟人」，聊再久也上不去。
- 下限**只在好感不为负时生效**：她可以对男友生气——好感掉到负数就是「冷淡 / 敌意」，
  不会因为"关系是男友"被翻回亲近。
- 老配置里没有这个字段：读进来时**按关系名从内置表补一份**（名字对不上的自定义关系保持 0，不瞎猜），
  所以已经在用的配置也自动修好，不用去改。

### 63. 关系表的「初始」改成单选，并修掉它接错线的问题

- 编辑器里那个「初始」复选框**改了基本没用**：运行时给新人建档读的是 `profile.default_bond`
  （一个名字），而复选框改的是 `bonds[].initial`——它只在"关系升级时该收掉哪个槽位"那里被读一次。
  勾错人的后果是新人照样挂"陌生人"，但升级时被收掉的是别的关系，通讯录里"陌生人"和"主人"并排出现。
- 现在统一成一个来源：关系表上方一个下拉「**新认识的人默认是：<关系名>**」，行内的复选框删掉。
  老配置里的标记读进来时自动搬过去。

### 64. 删掉从没生效过的 `allow`

- 分级表里的「允许的动作」**从来没有被运行时读过**（只有 `deny` 会写进提示词），
  却摆在那儿让人以为"每加一个动作都要来配一遍"。默认数据里「特别的人」那档的提示词
  还写着"亲昵动作都可以（按你配的允许范围）"——指的就是这个死字段。
- `allow` 从模型、编辑器、默认数据里一起删掉；「特别的人」那句提示词改成不提"允许范围"。
  分寸还是靠"这一档还不能做 + 模型自己克制"，加动作不用来这里配。

### 65. 关系那一段提示词重写

- 「现在还不能：…」改成「**这一档还不能做：抱抱、亲亲…**（你们现在是「熟人」这一档）」，
  并补上"**不做，也不提**；他开口要，用你自己的语气拒掉或者把话题岔开（可以带情绪、可以嘴硬，
  但别答应、也别做完再说）"——以前只写了"不能"，没写"怎么拒绝"。
- 原来那句"动作按距离分档"的四级阶梯不再全铺：只讲**再熟一点才到「下一档」**，
  用不上的档位不塞给她。
- 负面关系（讨厌的人 / 敌人）补了一条统一规则：不主动找、不撒娇、不做亲昵动作，他套近乎就冷淡回掉。

### 66. 设置页：低频字段收进「高级设置」

- 全局设置一共有 27 个小节、约 133 个字段，全部展开，新用户第一眼就被淹。
  现在**低频但一个都不能少的字段**（频率、预算、上限、阈值、"再压几条"这类）收进每节底部的
  「高级设置（n 项）」，默认收起；先做最吵的四节：**事件、上下文、图片转述、说话节奏**
  （这四节占了 133 里的 59）。
- 顺带修正两处过时的字段说明：「每小时最多被动回复次数」写的是"默认 15"（实际早已调整），
  「每小时最多生成发言次数」写的还是"超出后改用内置短句池"——那个池子已经删了，现在是保持安静。

### 67. 角色卡独占一行，被动回复默认改成 200

- 角色卡是这一页最该先看的字段，以前却跟别的字段挤在两列网格里（`.settings .fields` 只让带 `full`
  的元素跨列，而多行文本框默认没带）。现在它整行铺开。
- 每小时被动回复上限默认 15 → 40 → **200**（填 0 = 完全不限制）。这条是防"大群刷屏"的兜底，
  默认值调高之后它只在真的异常时才起作用。

### 68. 「倒杯茶」改名「倒茶提醒喝水」

- 这个动作本来就是"递杯水顺便催他喝一口"的意思，旧名字只说了动作、没说目的，
  她选它的时候也不会往"提醒喝水"上想。名字、动作文案、说明一起改成这个口径。
- 老配置里存的还是旧的那套：**只有字段没被你自己改过时才跟着更新**
  （改过名字或文案的保持原样），所以不用重新应用预设。

### 69. 接管没接上时：**保持安静**，并留下原因

- 「接管回复」失败时（模型调用挂了、或者模型没给出能执行的动作）以前会**交回主人格**——
  于是用户看到的是"她"突然换了个说法，因为那是另一个模型在替她说话。现在这种情况
  **这一条就不回了**（不注入、不回落），宁可少回一条，也不要让她换个人。
- 更关键的是**留下痕迹**：以前只在开着调试时打一行 stdout，插件的日志页里什么都没有，
  用户只能看到"她没回话"。现在失败原因会写进日志页（`这条没接上，她没说话：<原因>`，
  带模型给的告警与回复结尾），不用再靠猜。

### 70. 事件后续两幕的落点对齐

- 她遇上事时可以自己决定"这件事说给哪个会话听"（`send_to`）。这个选择以前**只在第一幕生效**：
  后面的「没人接的轻提醒」和「超时自己收尾」会落到当时 tick 的那个会话上——
  于是"我在私聊里跟他说这件事"会跑到群里去。现在两句都按当初挑的落点走。

### 71. 声音样例与候选池：跟着"保存"走，不再各写各的

- 以前「采用候选 / 编辑样例」会**直接写盘**，但编辑器内存里那份配置不知道——
  随后点右上角「保存」就用旧的那份覆盖回去，看起来就是"挑完候选一保存就没了"。
  现在样例和候选池跟别的设置一样：改的是编辑器内存，标脏，点保存才落盘。
- 「生成候选」要调一次模型（几秒到几十秒），以前**没有任何进度提示**，
  点下去就像没反应。现在按钮会置灰并显示"生成中…（要调一次生成模型）"，
  「从近期聊天挑」同理；没选会话时也会明确提示。

### 72. 记忆整理看得见了

- 记忆整理其实一直在跑（真机数据：113 条记忆里 79 条已经整理成要点、68 条被折叠过），
  但列表只渲染正文——整理过的和没整理过的长得一模一样，看起来就像"只整理了用户画像"。
- 现在每条标出**「已整理成要点 / 原文」**，并新增「详情」：一次看全整理状态、
  要点正文、**整理前的原文**（原文没删，一直收在 `context` 里）、相关的人、回访时间、
  整理时间、来源、权重。
- 记忆页顶部多一行「**上次整理**：合并 10 条、折叠 52 条…」——不写这一行，
  "记忆没变化"永远只能靠猜。

### 73. 调试页：声音样例单独点出来

- 声音样例排在提示词第 2 段，而自主提示词将近两万字，靠肉眼翻基本找不到。
  现在预览结果最上面单独一行：**本轮抽到 3 条**，连各自属于哪个场景一起列。

### 74. 几条默认值与观感

- 留档超限默认改成**压成摘要**（原来是直接丢弃最早的）；攒够 **30 条**就压一次
  （原来 80）；两次压缩至少隔 **10 分钟**（原来 60）。
- 「想念」那个小标题现在独占一行（它以前和后面的字段挤在同一格）。
- 已采用的样例：编辑按钮不再跑到中间（两个按钮时，只有第一个该往右推）。
- 关系表「新认识的人默认是」后面那串解释去掉了。

### 75. 「手感」滑块：一个滑块调一组参数

- 新用户脑子里想的是"话多话少""粘不粘人"，不是 `max_llm_text_per_hour`。新增 7 个滑块
  （**主动说话频率 / 群聊活跃度 / 私聊粘人程度 / 一次说几句 / 情绪起伏 / 生活丰富度 / 记忆勤奋度**），
  每档同时改一组本来就得一起调才自洽的字段——自主发言上限调高了、预算还卡着，行为会自相矛盾。
- 三条规矩：**每个滑块的字段互不重叠**（不然拖完 A 再拖 B，A 就白调了）；
  **中间那档 = 内置默认值**（老用户拖到中间等于没改）；**明细可展开**，
  看清这一档到底改了哪几个数——只有滑块没有明细就是黑箱。
- 拖动只写它管的那几个字段；你之后手动改了其中某个值，滑块旁会标一句「已手动调整」。
- 滑块在两处：设置向导里一屏，以及「说话与决策 → 手感（滑块）」随时可以回来调。

### 76. 设置向导

- 第一次打开编辑器自动走一遍：**她在哪儿生活（会话）→ 她是谁 → 模型检查 → 手感 → 记忆与画像**，
  最后自动保存一次。全局设置顶部有「重新运行设置向导…」，随时能重跑（每一步预填当前值）。
- 第一步有个「**重新获取**」按钮：让 bot 加完会话（`/vw session add`）之后点它把白名单拉回来——
  顺带修了一个坑：只更新界面的会话列表、不同步内存配置的话，随后点「保存」会把旧白名单写回去，
  刚加的那个会话又没了。
- 模型那一步只做检查（显示 7 个槽位现在指向哪个 Provider），不改配置——它们本来就在 AstrBot
  的插件配置里，编辑器改不到。

### 77. 内置默认世界不再另存一份默认值

- `DEFAULT_WORLD` 里重复写了一份 `limits` / `context`，**已经和模型默认值不一致**：
  改了模型默认值，"新建默认预设"却会把旧的保守值又装回来（真的发生过）。
  现在这两节只有一处真源（`core/models.py`），并加了测试钉住。
- 已经在用的配置里那些"还停在旧版默认值"的项（例如 `max_replies_per_hour=15`、
  `chat_overflow=discard`）**只报一句提醒、不替你改**——值分不清"没动过"和"特意选的"，
  悄悄把丢弃改成压摘要会动到成本，把 15 改成 200 会动到防刷屏上限。

### 78. 好久没来的人回来了，她会打个招呼

- 群里有人隔了大半天（默认 **12 小时**）又冒头时，提示词里会补一句
  「这人好久没来了，刚回来了——**可以戳一戳 ta 并打个招呼**，一句话就够，别追问人家去哪了」。
- 防刷屏三道闸：**每人每天最多一次**、**全群每天最多两次**、只在群里算（私聊本来就一对一）；
  提过一次就把这一笔销掉，不会连着几轮说同一句。

### 79. 关系熟了之后，她会主动问那些还不知道的事

- 画像里已经有的（他说过的）不会问；**没写进事实里的**才会进「你还不知道他的事」那一段
  （默认要问清：性别 / 生日 / 年龄 / 时区 / 所在地，可改）。
- 三条闸门：**从「熟人」那一档才开始问**（刚认识就问生日像查户口）、
  **同一个人一天最多提一件**、**同一件事 7 天之内不重复问**；每天全群最多 3 件。
- 由她自己找时机（提示词里写明"别在人家正说着别的时硬插"），问到就走现成的「记住」落库。

### 80. 心事：她心里会一直搁着一件事

- 新增 `heart_knot`（她自己在回复 JSON 里可选写一句）：「他上次那句话到现在还别扭」
  这种——**不推进、不解决，只是挂着**。和「事件线」的区别是：那是她在做的事，这是她自己的心事。
- 心事会**自然淡掉**（默认每小时 -0.02，约两天淡完），最多挂 5 天；说出过、淡完或到期就写进记忆放下。
  同时最多搁两件，所以不会变成一个整天苦大仇深的人。
- 提示词里会写"这些不是任务，只是你心里还惦记着"，并要求**别反复念叨、别硬把话题拽过去**。
