# 作息与节奏

[文档目录](README.md) · [按主题拆开的详细说明](GUIDE.md) · [返回 README](../README.md)

睡觉与被打断、她多久会自己动一次、一轮能排几个动作。

## 睡觉与打断

她睡着（或小睡）时不会跟人聊天。这道门禁挡在**两条回复路径之前**，比「接管 / 注入」的岔路口还早：

| 情况 | 结果 |
| --- | --- |
| 睡着了，有人 @ 她但没有唤醒词 | 只回一句固定文案（默认 `zzz…（{bot}睡觉中，要叫她起来吗？）`），不调大模型、不执行动作、不写互动记忆 |
| 睡着了，消息里带唤醒词**且** @ 了她 | 打断睡眠：停下当前动作、清掉排队的计划、给一段保护期，然后正常回复；同一条消息里交代的事照做 |
| 睡着了，但被吵得厉害 | **迷糊惊醒**：半睡半醒回两句（默认 3 分钟），然后接着睡**同一段**觉；一段睡眠最多一次 |
| 睡着了，群里别人说话（没 @ 她） | 整条消息被挡下：不回复、也不交给主人格，**其它插件也不会执行**（省掉一次判断） |
| 没在睡 | 一切照旧 |

### 临睡期：到点了也不马上躺下

真实的人不会一到点就断电。规则或她自己决定要睡的那一刻，插件**先把状态切到「临睡期」**，
把"睡觉"这一步揣在手里，过一会儿再真的躺下：

| 情况 | 结果 |
| --- | --- |
| 进入临睡期 | 计划里那一步睡觉被单独收起来，手上的动作清空；提示词开始告诉她"困得不行了" |
| 安静待够 | 默认 5 分钟后真的躺下 |
| 一直有人跟她说话 | 最多拖到 30 分钟，到点照样睡——没人愿意在沙发上坐到天亮 |
| 临睡期被 @ 她 + 唤醒词 | 当成"别睡了再陪我一会儿"：丢掉睡觉那步、状态回到清醒 |
| 「起床气」和「这段睡眠算不算同一段」 | 都不受影响：她还没真睡着，这些都从真躺下那一刻开始算 |

只有**夜里睡整觉**走这一套。白天的小睡、以及透支之后的强制补觉都不拖：前者是打个盹，
后者是她真的撑不住了。临睡期里计划也停着——同一串安排在睡觉后面的步骤要等她睡下再继续，
不会趁她打盹的时候抢着做。

临睡期里提示词会写明：说话短、断断续续、迷迷糊糊的，别主动挑话题。所以看起来是
「她已经开始犯困了、话变少了」，而不是「上一秒还在聊、下一秒直接不动了」。

**晚安与早安是她自己的事**。睡前和睡醒各问一次大模型，她可以决定发不发、发到哪个会话
（群里、私聊、或者两边都说），也可以选择不发——空计划就是不吭声。一天各只会问一次。

配置在「全局设置 → 睡眠与打断 → 睡前与睡醒」：

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| 临睡期 | 开 | 关掉就退回"到点直接躺下" |
| 临睡期多久才真睡 | 5 分钟 | 这段时间里安静就按时躺下 |
| 临睡期最多拖多久 | 30 分钟 | 一直有人跟她说话时的上限 |
| 睡前说晚安 | 开 | 由她自己判断发不发、发给谁 |
| 睡醒说早安 | 开 | 同上 |

### 迷糊惊醒

现实里被群里刷屏吵醒，人是会迷迷糊糊回一句再倒回去睡的。这条就是补上这一档——它既不是"完全不搭理"，
也不是"真醒过来"：

| 触发条件 | 默认 | 说明 |
| --- | --- | --- |
| 睡着了 | — | 睡整觉和小睡都算 |
| 睡下够久 | 30 分钟后才可能 | 刚睡着那段最沉，也正撞上第一次记忆整理；整理期间不会惊醒 |
| 群里够吵 | 5 分钟内 8 条 | 小睡门槛更低（5 条），沙发上被吵醒更常见 |
| 或者被反复点名 | 2 次 | @ 她、私聊、或者消息里喊了她的名字 |
| 这一段还没惊醒过 | 最多 1 次 | 不然整晚都会被喊起来 |

醒来的这三分钟里：**只允许说话和想事情**（不许出门、不许开长动作，代码里会把别的动作丢掉并写进日志）、
语气迷糊、可以带起床气、偶尔打错一两个错别字；回完就安静睡回去。
被吵醒会**扣固定精力**（默认 -0.05）——吵醒是有代价的，不会白送一次清醒。

关键的一条：**惊醒不是真醒**。她的状态一直留在"睡觉中"、手上的睡眠动作也没被打断，
所以这一段睡眠的记忆整理不会重新计时，**接着睡的还是同一段觉**；也不会给"刚被叫醒"那段保护期
（那个保护期是给真被叫醒用的，会拦着她回去睡）。想彻底叫醒她，还是用唤醒词。

「在跟她说话」只认**消息里真的 @ 了她**（或私聊）。这点很重要：意图路由那类插件放行消息时会把
`is_wake` 置 True，那是"这条消息要交给大模型"，不等于"有人在跟她说话"——只看那个标志的话，
睡着时它会以为有人在叫她，反而回一句 zzz。

配置在「全局设置 → 睡眠与打断」：

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| 睡觉时被叫怎么办 | 回固定文案 | 也可以选「完全不回」或「照常回复」 |
| 固定文案 | `zzz…（{bot}睡觉中，要叫她起来吗？）` | 支持 `{bot}`（她的名字）和 `{user}`（叫她的人）；留空等于不回 |
| 唤醒词 | 醒醒 / 起床 / 别睡 / 醒来 / 起来啦 / 别睡了 | 回车或点「添加」加一个，点词上的 × 删掉 |
| 必须 @ 她才算叫醒 | 开 | 群里有人随口说「起床了」不会把她弄起来 |
| 同一条回复的最短间隔 | 5 分钟 | 连着被 @ 也不会刷一屏 zzz，冷却期内保持安静；填 0 表示每次都回 |
| 叫醒后多久内不再自己睡 | 12 分钟 | 刚叫醒时精力往往还很低，没有这段保护期，规则几分钟内又会把她送回床上 |
| 小睡也按睡觉处理 | 开 | 关掉后只有「睡觉」会被拦，打盹时照旧聊天 |
| 叫醒时清空排队的计划 | 开 | 否则她被打断时排在后面的动作（例如几小时前想说的那句话）会在睡醒后突然补发 |
| 睡着时连其他插件一起挡下（方案 A） | 开 | 关掉就退化成「方案 B」：只保证本插件不出声，别的插件照常处理 |
| 挡住哪些消息 | 只挡没 @ 她的 | 也可以选「除指令和唤醒词外全挡」（连固定文案也不回） |
| 迷糊惊醒 | 开 | 关掉就只剩"固定文案"和"明确叫醒"两档 |
| 吵的窗口 / 条数 | 5 分钟 / 8 条 | 睡整觉的门槛；小睡单独一档（默认 5 条） |
| 被点名几次算吵 | 2 次 | @ 她或喊她名字都算 |
| 睡下多久内不惊醒 | 30 分钟 | 0 = 一睡下就可能被吵醒 |
| 一段睡眠最多惊醒几次 | 1 | 0 = 不许惊醒 |
| 迷糊窗口 | 3 分钟 | 过了就安静睡回去 |
| 被吵醒扣多少精力 | 0.05 | 固定值 |

叫醒之后群名片也会立刻从「睡觉中」改回来，不用等名片同步那 60 秒冷却。

### 阻断是怎么做到的

挡下这条消息的钩子注册在**比意图路由更高的优先级**（意图路由是 100，这里取 200）。
AstrBot 的处理器按优先级从高到低执行，而 `event.stop_event()` 会让后面的处理器不再执行
（`StarRequestSubStage` 每轮都检查 `event.is_stopped()`）。所以睡着时：

- 没 @ 她的消息：在这里就被截住，意图路由根本不会跑，既省一次判断，也不会把睡着的她拖进对话；
- `@她`：放行 → 回固定文案；带唤醒词的 → 叫醒；
- `/指令`：永远放行（否则 `/vw status`、`/vw 叫醒` 这些就用不了了）。

被挡下的消息仍然会记进她的聊天留档，醒来能看到群里发生过什么。

**和意图路由的配合（方案 C）**：插件在状态快照里多给了一个 `sleeping` 字段。装了
`astrbot_plugin_intent_router` 时，它会读到这个字段并把放行阈值推到 1 以上（任何置信度都不放行）——
两端的判断口径一致：**她睡着 = 不判断**。即使把「方案 A」关掉，也不会再出现"睡着还被拉去回话"。

### 被叫醒时提示词会说什么

两种回复模式都会带上同一句：

> 你刚被叫醒，可以迷糊一点；但对方如果在同一条消息里交代了要做的事，先把那件事写成动作，再回一句话。

消息里除了唤醒词还说了别的（例如「醒醒，去书房帮我查新闻」）时，再加一句
「对方不只是叫你起来，还交代了事情」。这样既保留"刚醒"的演出，又不会出现
「只应了一声、把她交代的事忘了」。

日志页能看到这道门禁做了什么：`她在睡觉，只回了一句固定文案：…`、`她在睡觉，没有回复（…）`、`被 xxx 叫醒`。

### 起床气

睡醒会结账，两种来源都会让她带着点气：

| 情况 | 结果 |
| --- | --- |
| 睡满整觉（默认 6 小时以上、中途没被吵醒） | 清爽：效价 +0.08、心潮 -0.05 |
| 睡够了但中途被吵醒过 | 清爽打折，并带一段轻起床气 |
| 没睡够就醒了 | 起床气：效价 -0.12、心潮 +0.10，默认持续 30 分钟 |
| 被吵醒（迷糊惊醒） | 起床气：效价 -0.05、心潮 +0.06，默认持续 15 分钟 |

起床气生效期间，提示词里会写明「你现在有起床气：说话短一点、耐心少一点，别主动撒娇示好」。
数值与时长都在「全局设置 → 睡眠与打断」里配。


## 她多久会自己动一次

### 一轮里的多个动作会排队

她手头有正在做的事时也可以照常安排接下来的动作：**新的安排会排队，等手上这件事做完接着做**，
不会被打断，也不会把她原本没做完的安排顶掉——原来剩下的步骤会接在新安排后面（先做主人刚说的，再回去做她自己的）。

**明确的打断**：如果对方说的是「别做了 / 不用了 / 停」，她可以真的停下来。这时模型会在回复里
带一个 `cancel` 字段，两档：

| 取值 | 行为 | 典型说法 |
| --- | --- | --- |
| `now` | 立刻停手，并放弃还没做的安排 | 「别查了」「停下来」 |
| `queue` | 手上这件做完，但不要再按原计划走 | 「后面的不用了」 |

**模型写了就照做**：不再拿"消息里有没有『别』字"当门槛——否则会出现她嘴上说不干了、
身体还在接着干的情况。提示词里已经限定"只有对方明确要求时才写"，写错由模型负责。
唯一的例外是动作自己标了「不可打断」（例如睡觉）：那件事不做一半就扔，但剩下的安排照样放弃。
每次取消都会在日志里留一条「按对方说的停了」。不想依赖模型的话，用 `/vw debug stop` 直接停手 + 清空安排。

如果她一次决定"先去书房，再上网查"，插件会先开始走路，把后面的动作排进计划，
等上一个动作做完再接着做——不会边走边说，更不会后一个动作把前一个顶掉。

排队的只有"要花时间的动作"：**说一句话不该等她把沙发瘫完**。她正在做的事如果不属于这一轮
（例如几十分钟前就开始的发呆），这一轮里的话照样当场说出口；反过来，如果这一轮自己开了
一个新动作（先走过去、再查一下），那后面的话才排在它后面，等她到了再说。
排队排到后面的**回话**按"回话"发，不受「主动发言冷却」影响（不然对方永远等不到那句回应），
而且中途被别人顶掉的那一步算过去了，不会做完新的事又回去把旧动作做第二遍。

### 走到一个新地方会就地做一次决策

她特地走到某个地点后，插件会**立刻**看看"这儿能做什么"，而不是等下个评估周期：
这一步直接问大模型，不看概率抽样、也不占「每小时最多自主行动次数」的额度
（它有自己的上限「每小时最多抵达决策次数」，默认 12 次，在「说话频率与预算」里调）。
所以像"让她去书房查新闻"这种事，走到之后就会接上搜索，不会愣在那儿。

**但"移动之后本来就有安排"时不会再问这一遍**：同一串动作里的下一步、或者计划里排好的下一步
（例如 `[walk_to 书房, search_web]`）落地后直接接着做；这一问只留给"只移动、没说到了要干什么"的情况。
日志里会写 `落地后已经有「上网搜索」，不再额外决策`。

### 「想做的事在别的地方」怎么处理

动作可以限定「只在某个地点可用」（例如上网搜索只属于书房）。遇到这种情况有两道保险：

1. **提示词要求她一次写全两步**：可达表里写明了每个地方能做什么、走过去要几 tick，
   协议里也有硬规则——「想做只有别处能做的事，必须写两步：先 walk_to，紧接着把要做的那件事
   也写进同一串 actions（只写移动不算安排）」，以及「在 say 里承诺了要做什么，就必须把动作也写进 actions」。
   写成一步是她最容易犯的错：那样插件只好带她走过去，到了之后再问一次模型要做什么，白白多花一次调用。
2. **万一她只写了动作、忘了写移动**：插件会替她补上那一步（日志里标注
   `↪ 她想去别处做这件事，已自动前往「书房」`），到了之后再执行那件事。
   这一层可以在「全局设置 → 动作与地点」里关掉：关掉后就变成"只有眼前能做的事才会被执行"，
   场景感更强但也更容易出现"她答应了却没做"。

真到了"落地后现决定"这一步（例如她只是想过去看看），那次调用也不是空的泛泛规划：
提示词会直接告诉她「你刚刚特地走到了「书房」，因为你打算：…，这里能做：…」，
让她一次就把该做的事排出来，而不是重新规划一整段时间。

注意：如果模型**连动作都没写**（只回了一句话），插件没有任何东西可以补救——
这种情况只能靠提示词降低概率。日志里现在会显示 `〔动作：say〕`，
一眼就能看出"她只说了话、没安排动作"。

### 日志里能看到什么

每条回复事件现在带三样以前看不到的东西：

- `〔动作：…〕`：这一轮解析出来的动作清单；
- `⚠ …`：被丢弃的动作及原因（例如"动作 fly 在当前场景不可用，已丢弃"）；
- 事件详情里的 `raw`：**模型的原话**（截断保存），用来判断是"模型没写"还是"被丢了"。

工具调用则统一记一条 `tool` 事件：调用哪个工具、**实际传出去的参数**、
返回了什么；失败时记 `✗ 失败：原因`，并且不会触发"就着空气说一段"。

自主行为这条链上有四个闸门，从外到内依次是：

| 闸门 | 在哪配 | 默认 | 作用 |
| --- | --- | --- | --- |
| 评估间隔 | 插件配置 → `decider_interval` | 300 秒 | 每隔多久评估一次「她现在想不想做点什么」 |
| 每小时上限 | 全局设置 → 每小时最多自主行动次数 | 2 次 | 一天里最硬的闸门：平均最快每 30 分钟做成一件 |
| 规则决策 | 动作/地图配置 | — | 困了回卧室、孤独了去大厅、无聊了换地方、好奇了去查东西、群里热闹又孤独就插一句 |
| 问大模型的概率 | 全局设置 → 自主决策 | 5%~40% | 这一次要不要**额外**交给大模型安排更丰富的计划 |

关键点：**规则决策不看那个概率**。规则命中就直接执行——比如她无聊值超过 0.8 想换地方，
这一轮就会安排移动，跟抽没抽中没关系。概率只管「要不要再问一次大模型」，
问到了就用大模型的计划（更细致、更贴合上下文），没问到就用规则的计划。

概率不是写死的，而是按**决策意愿**在两个上下限之间线性插值：

```
概率 = 下限 + (上限 − 下限) × 决策意愿
决策意愿 = 0.45×孤独 + 0.20×无聊 + 0.10×好奇 + 0.15×心潮 − 0.35×疲惫 − 被冷落惩罚
```

所以她是"闲得慌"还是"刚忙完很平静"，被问到的频率明显不同（实测，默认 5%~40%）：

| 状态 | 决策意愿 | 问大模型的概率 |
| --- | --- | --- |
| 平静待着 | 0.08 | 7.6% |
| 有点无聊 | 0.21 | 12.4% |
| 很孤独 | 0.42 | 19.7% |
| 心潮很高 | 0.41 | 19.2% |

想让她更常被大模型安排事情，把「概率上限」调到 0.6~0.8；想省 token、让她按规则过日子，
把上下限都压到 0.05 以下。当前意愿和实际概率会显示在「控制台」页的状态卡上（「互动与运行」小节里的「决策意愿」那一行）。

### 把过程发到群里看（调试回显）

排查"她为什么这么做"时，翻日志页不方便，可以直接让过程出现在群里：
「全局设置 → 调试输出」里**勾选想要的类型**（配置项 `world.echo_types`，默认一个都不勾 = 关闭）。
类型按用途分成七组（决定与动作 / 工具与指令 / 记忆与回想 / 日程 / 睡眠与保护 / 事件与线索 / 图片·上下文·名片），
每组可以单独全选或取消，旁边还有「全选 / 常用 / 清空」三个总控按钮。

同一块里的**「精简模式」**（`world.echo_compact`）勾上后只发要点、不发参数和结果：
排查"她做了什么"够用，也不会把群刷满。

开启后，回显的是**群里本来看不见的那些环节**——她自己说出口的话本来就会正常发出去，
不会再重复一遍。以"日程到点去书房查新闻"为例：

```
▶️ 开始「移动」，预计 1 个 tick，目标「书房」
✅ 做完「移动」
🔧 调用「web_search」参数 {'query': '今天的新闻'}
📥 「web_search」返回：今天有三条科技新闻…
查到啦，今天有条开源模型的消息。      ← 这句是普通的 say，只发一次
```

回显按**实际发生的先后**发出去：先调工具、拿到结果，然后才是她开口说话——
上面这个顺序就是群里刷出来的顺序。

可以勾选的类型和它们的前缀：

| 勾选项 | 前缀 | 事件 |
| --- | --- | --- |
| 她的决定 | 🧠 | 这一轮定了什么计划、为什么定、是谁定的（规则 / 大模型 / 日程 / 极端保护） |
| 开始动作 | ▶️ | 开始一个动作，带预计耗时；移动还带目标地点 |
| 动作完成 | ✅ | 持续动作做完，带工具返回结果 |
| 静默动作的内容 | 🎬 | 想事情这类本来不发到群里的动作写了什么（她自己说过的话不会重复发） |
| 调用工具 | 🔧 | 调了哪个工具、**实际传出去的参数** |
| 工具返回 | 📥 | 工具返回了什么；失败会写明原因 |
| 触发指令 | 🧩 | 指令型动作实际发出去的指令 |
| 指令返回 | 📤 | 那条指令返回了什么、有没有跑失败 |
| 被跳过的动作 | ⏭️ | 某个动作没做成的具体原因（缺必填参数、地点不对、工具不存在…） |
| 写了一条记忆 | 📝 | 一段对话被总结成记忆时发出来，方便对着看记得准不准 |
| 群名片变化 | 🏷️ | 她的群名片改成什么、有没有改失败 |
| 进入安静期 | 💤 | 连续主动说话没人回应，触发无人回应保护 |
| 极端保护 | 🚨 | 精力透支、太久没人说话这类兜底规则被触发 |
| 上下文压缩 | 🗜️ | 群聊留档攒太多、被压成摘要的时候 |
| 日程开始执行 | 📅 | 哪条日程开始跑了、是到点还是你点了「立即执行」、这一串要跑哪些动作 |
| 触发指令 | 🧩 | 指令型动作实际发出去的指令与对方的返回 |
| 被叫醒 | 🌅 | 她睡觉时被唤醒词叫起来 |
| 睡着时的回话 | 😴 | 睡着时被 @，只回了一句固定文案 |
| 睡着时没回复 | 🤐 | 睡着时被消息叫到，但按配置保持安静 |
| 遇到事件 | 🎰 | 她自己遇上了什么事（做饭糊了、锅盖卡住、群里吵起来…） |
| 事件抉择 | 🌙 | 这件事她打算怎么处理、派哪项能力值上 |
| 掷骰判定 | 🎲 | 判定的一行算式：能力值 × 情境修正 × 难度 → 掷骰 → 四档结果 |
| 事件结果 | 📖 | 结果是什么、能力值变了多少、还有没有后续 |
| 求助与建议 | 🆘 | 她开口求助、收到群友的回应、等超时自己收尾 |
| 挂起与收尾 | ⏳ | 线索挂起、过期、告一段落 |

只想要"她到底做了什么"，勾「常用」那六项（决定 / 开始动作 / 动作完成 / 静默动作 / 工具调用 / 被跳过）就够；
排查记忆准不准、睡觉门禁有没有生效时，再把 📝 / 🌅 / 😴 / 🤐 打开。

一段完整的日志长这样（含被跳过的情况）：

```
🧠 决定：上网搜索　〔原因：为了做「上网搜索」先移动过去；来源：auto_travel〕
▶️ 开始「移动」，预计 1 个 tick，目标「书房」
✅ 做完「移动」
⏭️ 跳过：工具动作「上网搜索」缺少必填参数 ['query']
```

这些消息只是播报，**不算她说过的话**：不会进聊天上下文、不会累加"主动发言没人理"的计数，
也不影响她的状态数值。所以可以放心在调试期间开着，排查完在同一个卡片里关掉即可。

想看到更细的（提示词原文、指令与参数、工具返回全文）还是看后台日志：那属于「插件配置 → 调试日志」。
