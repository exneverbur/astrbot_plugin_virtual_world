# 事件与能力值

[文档目录](README.md) · [按主题拆开的详细说明](GUIDE.md) · [返回 README](../README.md)

她自己遇上事、掷骰判定、开口求助的整套机制。

## 事件与能力值

除了日程和数值驱动的行为，她自己还会**遇上事**：做饭糊了、锅盖卡死、群里两个人吵起来、
打游戏卡在关键一局……一件事不是"一句话播报"，而是**一格一格往下走**：

```
遇到事件 → 她自己拿主意 → 掷骰判定 → 写结果 → 有伏笔就接着演下一步
```

### 频率怎么定

「全局设置 → 世界与事件 → 事件」里按**每小时大约几次**配（不是"每 N 分钟一次"——
固定间隔会带上整点感）：

| 档位 | 默认 | 说明 |
| --- | --- | --- |
| 微事件 | 1 次/小时 | 只影响她自己的状态和记忆，群里不主动说（会在她下一次续说里顺口带一句） |
| 小事件 | 0.3 次/小时 | 她要做个选择、会掷骰 |
| 大事件 | 0.02 次/小时 | 会说，也可能开口找人商量（约两天一次） |

另外两个门槛：**在一个地点待够 `dwell_minutes`（默认 5 分钟）**才算"在这儿生活"；
**睡觉时默认不出事**（想要梦里的剧情可以打开 `in_sleep`）。做持续动作（做饭、看书、发呆）
期间也会出事，可以关掉。

掷骰是**泊松近似**：`min(1, 每小时次数之和 × 距上次掷骰的小时数)`。两个容易踩的细节：

- 掷骰时钟**每个 tick 都推进**（睡觉 / 忙长动作期间不攒"欠账"），所以醒来不会"必定出事"；
  单次折算最多按 15 分钟算，tick 被拖慢也不会一次补出满概率；
- **两件事之间至少隔 `min_gap_minutes`（默认 30 分钟）**，刚收尾也不会立刻又来一件。

每次掷骰的时间差、概率和掷出的值都写在那条「遇到事件」的日志里（不用开调试输出也能查）。

### 能力值

四项：**体力 / 智力 / 灵巧 / 心性**。它们是**慢变量**——只由事件结果改变，睡一觉不会回来，
和「精力」不是一回事（精力管今天累不累，能力值管她平时的底子）。

判定写成一行算式，日志里能直接看到：

```
🎲 智力 0.58 × 有建议 1.20 × 疲惫 0.85 × 难度 0.70 = 0.41 → 掷 0.31 → 成功
```

结果分四档：**大成功 / 成功 / 勉强成功（带代价）/ 失败（长教训）**；
概率夹在 0.05~0.95，永远没有"必胜"和"必败"。护栏两档：单次最多变化 `step_limit`（默认 0.05）、
每天累计最多 `daily_limit`（默认 0.1）。**失败比成功更容易长能力值**——
这才是"同一件事失败了还能再试"的依据，不是靠文案鼓励。

提示词里给她的不是数字，而是人话（"你手挺稳的"）：她知道自己的手感，不知道 0.62。

### 她怎么判断"这么做行不行"

每个选项后面带一句**她自己的估计**：有把握 / 差不多 / 有点悬 / 基本没戏。
这不是客观概率——**心潮高会高估自己、精力低会低估**，所以"以为稳却翻车"和
"以为没戏结果成了"都会自然发生，落差越大她事后越有情绪。

### 没有事件池：每一件都按当前场景现编

早期的做法是"内置一批事件、按地点和动作挑一条"。这条路走不通：**写池子的时候不知道她此刻在哪、
在做什么、心情如何**，落到具体情境里总有一股"编的"味道；同一条被抽中两次，群友一眼就认出来。
所以事件池整个删掉了（连同配置项和编辑器那一页），**每一档都由生成模型现编**——包括微事件。

生成模型拿到的是：她是谁（简易人设）、此刻在哪做什么、当前心情与精力、代码抽中的题材、
你写的红线，以及她最近的几条记忆。事件包长这样（字段和模型输出一致）：

```json
{
  "title": "锅盖卡死了",
  "hook": "锅盖卡死了，蒸汽往外顶，手边只有一条毛巾",
  "tier": "small",            // micro / small / big
  "kind": "solo",             // solo（自己能处理）/ need_intervene（需要找人商量）
  "mode": "real",             // imagined = 发生在想象/游戏里，她的实际位置不变
  "place_name": "厨房",
  "difficulty": 0.5,
  "critical": false,          // true = 危险/紧急：没演完之前日程要给它让路
  "options": [
    {"desc": "硬掰", "abilities": ["stamina"]},
    {"desc": "先关火，再用冷水激一下", "abilities": ["wits", "dexterity"]},
    {"desc": "先撤开等它凉", "no_check": true}
  ],
  "followup": {"success": "锅盖弹开了", "fail": "手忙脚乱，灶台弄得一团糟"}
}
```

规则：**选项里必须留一个"能全身而退的"**（`no_check: true`），她永远有退路；
`followup` 决定还有没有下一步；微事件不掷骰，结果（`outcome`）、状态变化（`effects`）和能力值
变化（`abilities`）都由模型一次写全。

生成失败（没配模型、或者模型没给出可用的包）时**这一轮就当没出事**，不会塞一条假事件顶上；
日志里记一条 `event_skip`。

### 用户直接投递

```
/vw event 出门忘了带伞
```

她当场就会遇上这件事（等于"强行掷骰命中"）；不写内容就按当前场景现编。
权限在「世界与事件 → 事件」里的 `event_actor`：`admin`（默认）或 `all`。

**投递不看「待够几分钟」那条门槛**（那是给自动掷骰用的），刚走到一个地方也能立刻发生；
但她**正忙的时候直接拒绝、不排队**——在做饭、在走路、在睡觉都会明确告诉你原因，
免得你以为安排上了、其实一直没发生。等她闲下来再投一次就行。

`/vw event list` 看最近的事件线索，`/vw ability` 看她的本事，`/vw thread` 看手头没完的事
（能力值和线索**不公开**，这两条只有管理员能用，群友自己看不到）；
编辑器里有一个独立的「**事件**」页（左侧导航「观察」那一组）：上面能直接投递事件、看**现在这件事**的每一幕，
右边是「她的本事」能力值雷达，下面是「最近的线索」和历史事件。

### 成本

| 环节 | 用哪个模型 |
| --- | --- |
| 生成事件包 | 内容生成模型（**每一档都调**） |
| 她的抉择 | 主模型 |
| 结算（结果 + 数值变化） | **事件模型**（留空跟随打杂模型） |
| 掷骰 | 不调模型（纯计算） |

生成与结算的提示词都是**裁剪过**的：只带简易人设、她此刻在哪做什么、这件事的来龙去脉，
不带世界规则、动作表、聊天记录。微事件也要过一次生成模型（频率最高，但一次只调这一个）。

日志和调试输出里会标出每件事的来源：

```
🎰 遇到「锅盖卡死了」（厨房）｜临场生成：锅盖卡死了，蒸汽往外顶，手边只有一条毛巾
🎰 遇到「出门忘了带伞」｜用户投递：出门忘了带伞，外面正好下起雨
🎰 遇到「手背烫伤了」｜线索续演：得找个创可贴
```

### 什么时候说出来：分享策略

事件是**她身上发生的事**，不是"要演给群友看的节目"。以前醒着就每一幕都往群里发一句，
结果就是一个人没头没尾地尬演。现在微 / 小 / 大各有自己的策略（「世界与事件 → 事件」里配）：

| 值 | 意思 | 默认 |
| --- | --- | --- |
| `silent` | 只进状态与记忆，一声不吭 | 微事件 |
| `nodes` | 只在**开场和收尾**那两幕说，中间静默推演 | 小事件 |
| `always` | 每一幕都可以说 | 大事件 |

**不说不等于没发生**：状态、能力值、情绪、记忆照常动，收尾那一幕的结果还会作为一条
「她自己身上发生的事」写进聊天留档（标着 `internal`，不算"还没回的消息"）。
所以她日后聊天时能自然提起"我前两天把锅盖拧死了"，而不是每件事都只活在提示词的另一段里。
这份留档可以关掉（`event_into_chat_log`）。

### 大事件最少两幕

大事件一步收尾会显得特别潦草（"有人找我麻烦"下一句就是"我自己解决了"）。
`big_min_steps`（默认 2）到下限之前，**模型没留伏笔也由代码补上一步**；
两步之间还要隔 `big_step_gap_minutes`（默认 15 分钟），不然会连着刷屏。

### 题材：由代码按权重抽，不是让模型自己分配

只写"编一件她身边的小事"，模型会一路往温馨小事的偏上走——「被人跟着」这类题材一次都不会出现。
所以题材（「世界与事件 → 事件」里的**事件题材与权重**）是**代码掷**的：代码按权重抽一个题材，
再把"这一件属于【人际】"交给模型，它只负责在这个题材里编。

默认七类（权重可改，填 0 = 不生成那一类）：

| 题材 | 权重 | 例子 |
| --- | --- | --- |
| 日常小事 | 40 | 做饭、找东西、东西坏了、收快递 |
| 人际 | 20 | 被误解、拌嘴、被冷落、被搭讪、被人跟着 |
| 情绪与身体 | 15 | 失眠、头疼、太累、心里发闷 |
| 意外与麻烦 | 12 | 丢东西、下雨没带伞、走错路、手机没电 |
| 好奇与发现 | 8 | 看到奇怪的东西、翻到旧物、听到传闻 |
| 游戏与想象 | 3 | 打游戏卡关、看剧上头 |
| 外面的事 | 2 | 逛街、坐车、排队 |

另外三个开关：**最近几件用过的题材先不重复**（默认 4）、
**题材冷却**（默认 180 分钟——权重 40% 的「日常小事」光靠"排除最近几条"压不住，
隔一件就又回来了）、**题材的尺度边界**（默认留空 = 不额外限制，想收紧就写一句，
例如「不要写受伤」）。自订的题材也可以加，右边那栏是给模型的例子，写得越具体它编得越贴。

抽中的题材会记在线索上，日志里也标出来，所以你能直接看出"最近是不是全在演日常小事"。

### 日程撞上事件：日程闸门

她正处理一件事时到了日程点怎么办？运行规则是**先免费筛掉九成，只有真冲突的才问她**：

- **没有正在进行的事件** → 日程照常跑（一天里绝大多数）；
- 日程是**伸懒腰、吃饭、看书**这类 → 照常跑（一边等消息一边哼歌很真实）；
- 日程是**睡觉 / 小睡 / 换地方** → 交给她自己决定：
  - 这件事标了**危险 / 紧急** → 直接让路（不问模型）：被跟踪的时候不能回卧室睡觉；
  - 否则问一次主模型，三选一：**照常做 / 推迟一会儿 / 今天算了**；
- **推迟有上限**（默认 2 次 / 累计 180 分钟，谁先到算谁）→ 到顶就必须执行，睡觉没有商量余地；
- 推迟睡觉 = **熬夜代价**：这段时间精力衰减 ×1.5（可配），第二天状态是真的差。

事件的「危险 / 紧急」在事件编辑器里勾选（生成的事件也可以自己标），标上之后
它没演完之前日程一律让路。推迟的记录在日志里能查到（`⏭️ 日程「…」她自己决定先处理手上的事`）。

### 事件里的发言条数

平时群聊最多 2 句（情绪格和"话太密"还会再收），但**求助那种要分几条发的场合**给得宽松些
（「世界与事件 → 事件」里的**事件里她一次最多说几句**，默认 4；另有**硬顶**默认 6 防刷屏）。
结果那几句仍然最多 2 条——"有人吗 / 我这是… / 怎么办啊"才需要连发。

### 事件里她可以先去做点什么

遇到事的时候，她不是只能在给定选项里挑：**她可以先调一个动作把情况查清楚，再拿主意**。
抉择的输出分两态：

```json
{"phase": "act", "reason": "先查一下", "actions": [{"type": "search_web", "intent": "查这个型号的说明书"}]}
{"phase": "decide", "pick": 1, "reason": "有资料了"}
```

哪些动作可以这么用，按下面的顺序决定：

1. 动作编辑里的 **「事件中可调用」**（跟随规则 / 强制允许 / 事件中禁用）；
2. 「跟随规则」时：**工具型 / 指令型**动作算可用，会主动往群里发东西的那类（`target_type=group`）排除；
3. 再筛一遍"真的跑得起来"：工具动作得挂着已注册的工具，指令动作得有指令名。

执行时动作结果**只交回给她判断**，不会当成她的话发到群里（要说的话留到拿主意那一轮）；
一次事件最多调几次由「一条线索里最多调用几次动作」控制（默认 2，0 = 完全不给）。
群里刚有人建议"你搜一下"，这条建议会进抉择提示词——现在她是真的能搜。

### 事件里的图

每一幕推进 / 完结时，她可能顺手拍一张发出来（「每一幕出图的概率」默认 0.3，「事件出图用哪些动作」
默认 `selfie, take_photo`）。触发时会把**这件事的内容**（标题、发生了什么、她的选择和结果）
写进出图意图，所以照片和剧情对得上。生图动作本身要装好对应的图片插件、并在动作库里启用。

### 她自己的账：记得住，但不被绑住

提示词里带着三段"她自己的账"，在「世界与事件 → 她自己的账」里配：

| 段落 | 里面是什么 |
| --- | --- |
| 我正在经历 | 手上那件事的详细处境：发生了什么、她已经选过哪条路、还差什么 |
| 最近发生在我身上的事 | 时间窗口内（默认 24 小时）经历过的每一件，从早到晚一条一行，带「今天 / 昨天 / 前天 + 时间」 |
| 有件事我心里还挂着 | 下一步要等很久的那些事，只留一行轻提示 |

三条规矩：

- **下一步要等超过 `suspend_after_minutes`（默认 30 分钟）的事算"挂起"**：它不再占「我正在经历」那段——
  中间这几小时她在做饭、看书、接群聊，不该被一件还没到点的事绑着；
- **「最近发生在我身上的事」最多 `recent_max_lines` 条（默认 8）**：超了**先顶掉微事件**（最旧的先走），
  再顶最旧的。微事件只影响状态和记忆，不留着她也能过；
- 记忆按**这件事发生的地点**落点，不是她此刻站的地方：在窗边"想起"的逛街被跟，记在商业街，
  以后按地点搜得到。

### 分集：一件事可以隔一阵再接着演

有伏笔的事不会一口气演完：她先收尾这一段，过一会儿（`step_gap_seconds`，默认 60 秒）再续，
中间照常做别的事。

- 续演时她**人在别处**（逛街那件事在商业街，她这会儿在书房）：这一幕按"又想起了它"演，
  提示词里会写清"你只是又想起了它，别说自己此刻在那里"，不会把场景搞混；
- 一件旧事隔太久（`thread_resume_max_hours`，默认 24 小时）就不再续演，直接收尾，
  记忆里留一条「那件事后来没再提」。

### 连发两条只回一次

你连着 @ 她两次时，她不会各回一条：**她还在调模型、还没开始发送**的那几秒里
（默认 5 秒窗口，最多合并 1 次、最多并 3 条），新消息会被并进这次请求重新发起，
一次把两句都回答掉；第二条自己就不用再回了。窗口之外来的消息照旧排队各回一条
（宁可多说一句，也别一直不说话）。日志里会有一行"合并成一次回复重新发起"。


## 她开口求助

需要拿主意的事（问路、借东西、收到陌生人的消息、两个选择拿不定），她**会在群里问**——
和真人一样分几条发（"有人吗" → "本小姐好像迷路了" → "怎么办啊"），不是选项按钮。
群友的回应会先经一道分拣：

**只有群里真有人时才开口。** 最近十来分钟里谁都没说话，她就不会喊那一声「有人吗」——
空群里喊一嗓子只会等到自己，于是这一条直接改成她自己拿主意（结果照样进记忆和日志）。
同理，她**睡着（含小睡）时事件照演，但不在群里出声**：不然群友会看到"她说自己在睡觉、却在群里讲话"。
每一幕要说的话也要求自带前因（"有人想拿本小姐当免费传话筒，想得美"），别只丢一句反应。

- **只丢和这件事完全无关的**（比如旁边在聊今晚吃啥）；
- 建议、起哄、打气**都留着**：建议改判定概率，起哄和打气改她的选择
  （被激将了可能选更莽的做法，那就更容易翻车——这不是有人在背后改骰子）。

### 三个等待状态（等待不是冻结）

| 状态 | 时间 | 她做什么 |
| --- | --- | --- |
| **活跃等待** | 默认 180 秒（`active_seconds`） | 注意力在这件事上；有人回应就优先处理。她**照常做自己的事、照常接群聊** |
| **轻等待** | 到总超时（`idle_minutes`，默认 60 分钟） | 不再主动提这件事；有人提起就接一句，有人问她那件事还能回到活跃等待 |
| **已放弃** | 超时之后 | 按她自己的判断收尾、写记忆（"那天想找人帮忙没找到"） |

活跃窗口到点只发**一次**轻提醒（"算了，本小姐自己来"）然后降级；等不到人她自己动手，
不会一直刷屏。**她不会因为"正在等"就不说话**——这是刻意的：等待是背景状态，不是冻结。

### 和意图路由的配合

装了「智能意图路由」的话，她求助的那几分钟里路由会**合并放行、跳过回复冷却**，
让群友的回应尽快交到她手里；问不到虚拟世界或调用超时，路由照旧工作。
