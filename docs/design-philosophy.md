# 设计理念

[返回 README](../README.md) · [文档目录](README.md) · [详细说明](GUIDE.md)

这份文档不教你怎么点按钮，只解释两个问题：**为什么做成这样**，以及**它的边界在哪**。
理解了设计意图，配置起来会顺很多——遇到「她今天怎么不想我」这类情况时，也更容易判断是设计如此还是配置需要调。

## 一、她不是「换个皮肤的回答机器」

大多数拟人插件的做法是：消息来了 → 拼一段人设提示词 → 回一段话。
回复这件事本身没错，但那样她只有「此刻」，没有「之前」和「等会儿」：
关掉对话窗口，她就不存在了。

所以这个插件的第一条设计原则是：**她有一条自己的时间线，独立于你的消息。**
后台世界时钟持续推进，按日程起床做饭、按数值决定去睡还是去找人、走到公园顺手拍张照。
你不说话，她的生活也在继续；下一次你开口时，她已经有了一段你没参与的最近经历。

代价是复杂度：地图、动作、日程、状态、记忆、事件都要有地方配，也就有了后面这些页面。

## 二、闭环：一切都互相喂养

> **事件驱动记忆，记忆驱动关系，关系驱动情绪，情绪驱动决策，决策驱动事件。**

这是整个插件的骨架，不是营销话术：

| 环节 | 谁在做 |
| --- | --- |
| 事件驱动记忆 | 发生的事会写进她自己的账，按发生的地点落点，而不是她当时站在哪里 |
| 记忆驱动关系 | 与某个人相关的事会进通讯录，改变画像、印象与好感度 |
| 关系驱动情绪 | 关系等级、好感度、想念程度会影响她此刻的心情与心潮 |
| 情绪驱动决策 | 精力 / 孤独感 / 好奇心 / 无聊 / 心潮 / 效价 决定她下一轮想做什么 |
| 决策驱动事件 | 她去做的事本身又可能成为一件新鲜事，回到第一步 |

闭环的意义是：功能之间互相喂养，而不是各管一段。
好处是她的行为经得起追问（「她为什么今天懒」有链条可查），代价是任何一环配错了，表现都会走样。
所以编辑器里到处都留了「概况」「提示」「预览」这类透明度补丁。

## 三、可解释，比神秘更重要

一个会自己行动的系统，最难的不是让她动，而是让你知道**她为什么动**。

因此：

- 她动手前先写推理草稿（在哪 / 什么状态 / 和谁说话 / 打算怎么办），你能看到她当时怎么想的。
- 每个决定、每个动作、每次「跳过」都写进日志，包括决策来源是规则、自主决策还是大模型。
- 事件的每一幕、每个判定都留档，掷骰时能看见完整算式。
- 调试页可以预览这一轮真正注进去的提示词、自主提示词和配置备份。

设计取向是：**宁可让你看见她算错了，也不要让你猜她在想什么。**
一个能被理解的角色，比一个永远正确但不可解释的角色更容易信任。

## 四、能配的都该能配

插件里几乎没有写死的内容：

地图、地点、连线耗时、地点氛围、动作文案、日程、事件频率、情绪量程、提示词片段、声音样例、
关系种类与亲密度阶段，全都在网页端可改；地图和动作还可以让大模型按你的主人格批量生成。

但「全都能配」不等于「都要你配」。默认世界（5 个区域 / 21 个地点 / 76 个动作 / 3 条日程）
是能直接开箱用的，设置向导会替你决定大部分数值。
配置的层次感是有意设计的：**大部分人可以只跑一遍向导，想深入的人永远能找到那个开关。**

## 五、分层：贵的模型只说该说的话

她的每一次「开口」都很贵——要带上下文、记忆、状态、可用动作。
所以把工作拆开：决策、整理、检索、看图、生成文案交给便宜的辅助模型；
主模型只负责真正需要质量的那一下。

同时提示词按「固定不变 → 低频变化 → 每轮变化」分层排布，让前缀缓存能命中，
既省 token 也省时间。这部分细节见 [Token 预算](context.md#token-预算)。

## 六、不是所有事都要说出来

一个常见的失败模式是：她的每一次内心活动都被广播出来，于是显得又吵又跳戏。

所以事件默认**静默推演**：平常只写进她自己的经历，
只在开场、收尾、需要求助这些节点才说出来。
同样地，连续主动说话没人理，她会自己进入安静期；接管失败时她安静放过这一条，而不是换个人格硬答。

**会忍住不说的角色，比每句都接的角色更像人。**

## 七、边界与提醒

- 她是**程序**，不是人。她的情绪来自数值和提示词，不是真实感受。
- 请把好感度、亲密度、关系这些系统当作**表达方式和相处节奏的调节器**，而不是真实情感的承诺。
- 她可以陪你、逗你、和你斗嘴，但不能替代真实的人际关系。如果发觉自己更愿意跟她说话而不愿意和人说话，那是需要停一停的信号。
- 数据都存在你自己机器上的插件目录里，没有上传；想清空随时可以在编辑器里删。

## 八、这一套的代价

诚实地说，这个系统的复杂度已经不太像一个「插件」了：
配置字段多、页面多、模型槽位多。我们清楚这一点，也一直在做减法——折叠次要项、精简说明、
把长文本改成弹窗、给每个数值配上一句人话解释。

如果你觉得某处仍然难以理解，那大概率是设计没做好，而不是你读得不够仔细。
